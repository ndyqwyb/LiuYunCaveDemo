#### 12.5.2 开发时常用控制台命令（Play 中按 `~`）

| 命令 | 作用 |
|---|---|
| `stat fps` | 显示帧率 |
| `stat unit` | 显示 Game / Draw / GPU 耗时（排查性能第一步） |
| `stat game` | 显示游戏线程各项耗时 |
| `t.MaxFPS 60` | 限帧，避免笔记本发热降频 |
| `r.ScreenPercentage 70` | 降分辨率渲染提帧（保留画质底线） |
| `r.VolumetricFog 0` | 关体积雾（本项目用不到，性能杀手） |
| `r.Shadow.Virtual.Enable 0` | 关虚拟阴影（性能不够时使用） |
| `ShowFlag.LumenDynamicGI 0` | 临时关 Lumen 动态 GI（对比性能影响） |

> 💡 命令只影响当前运行，不会写进项目。**确认有效后**再写进 `DefaultEngine.ini` 或后期处理体积。

## 第三部分 · 收尾与展望

### 12.6 给未来的你（项目结束后的建议）

1. **把这个项目的 DevLog 留着。** 它记录了你的成长，也是下次做项目的模板。
2. **下一个项目换一种类型。** 做完解谜，可以试试动作、平台跳跃、Roguelike——**广度会让你在面试里更有底气**。
3. **把 C++ 学扎实。** 这个项目让你「会用」，但要想进大厂，需要理解 UObject、GC、反射、网络同步这些底层。
4. **保持对原版游戏的「拆解习惯」。** 玩任何游戏都问：这个机关怎么实现的？这个引导怎么做的？**这是关卡/玩法策划最值钱的能力。**
5. **不要只做复刻。** 复刻是学习，但面试官更想看到你有**原创的设计判断**。做完这个项目，试着加一个「原版没有的机关」，并讲清楚为什么加。

### 12.7 关于「是否继续做奥藏山前置」

《关卡设计》（`02_关卡考据与设计.md`）的阶段 0 提到了「奥藏山三把石椅 → 做三道菜 → 供奉」的前置流程。

**结论：不做。**

理由：
- 它是一个**独立的烹饪交互系统**，会额外花 1～2 周。
- 它对「洞天机关」这个核心主题没有帮助。
- 它需要额外的场景和 NPC 美术。
- **它是 P2，做了不加分，不做不扣分。**

> 如果你想加，**放在 v2.0 的路线图里**，不要放进这个 12 周计划。
