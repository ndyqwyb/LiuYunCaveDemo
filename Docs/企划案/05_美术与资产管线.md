> 本章回答：**一个不想做美术的 gameplay 程序，怎么用 Tripo3D + 免费素材 + 后期描边，做出“风格统一、一眼能认出”的画面。**
> 前提：你已决定大型建模用 **Tripo3D**，角色用 **VRoid**，不做官方旅行者模型。

## 第一部分 · 美术方向与风格规范

### 5.1 设计宣言

> **悬浮在青碧虚空中的仙家遗迹：多座浮空石台，由金色发光的光路连接，火与石构成机关，静谧而庄严。**
>
> 玩家不是被敌人阻拦，而是被**空间本身**考问。

这套美术规范服务于一个目标：**用最少的建模工作量，做出「风格统一、一眼能认出是洞天」的画面。**
你主要练 gameplay，所以本规范的所有决策都偏向「**降低美术成本、提高风格一致性**」，而不是「逼近原神画质」。

### 5.2 全局基调

| 维度 | 设定 |
| --- | --- |
| 场景类型 | 悬浮于青碧虚空的**洞天秘境**，多座浮空石台 |

| 光源逻辑 | **天空即主光**；金色光路是第二光源；火柱是局部红光；**没有洞穴暗部** |

### 5.5 机关视觉语义（严格遵守，不得例外）

> 原神的机关之所以「一眼就懂」，是因为**同一状态在所有机关上都长得一样**。你的 Demo 也必须这样。

| 状态 | 视觉表现 |
| --- | --- |
| 可交互 · 未激活 | 淡青蓝色呼吸光（`#7FE0EA`），慢速脉动，周期约 2 秒 |
| 已激活 | 稳定金色光（`#FFD98A`），纹样点亮，**不再脉动** |
| 不可用 · 锁定中 | 完全无光，材质发暗发灰（`#7E948F`） |
| **被封印（宝箱/火方碑）** | **半透明发光能量罩**包裹 + 缓慢脉动（约 2s）；破除时溶解消散（`3.26`） |
| 需要玩家前往 | 细光柱 / 粒子流指向目标方向 |
| 谜题完成 · 全亮 | 全场统一金色，可加一次「扩散光波」 |

> ⚠️ **火柱「点亮/熄灭」的红色火焰与「光路接通」的金色是两套语言，不要混用。**
> 火柱 = 红橙（`#B2354A`~`#FF5C3A`）；光路/机关激活 = 暖金（`#FFD98A`~`#E8A33D`）。

### 5.7 打光原则

1. **天空即主光。** 先做好天空球 + 指数高度雾，再考虑其他灯。天空对了，画面就对了一半。
2. 优先用**光照对比**引导，而不是 UI 文字：**每个「该去的地方」必须比周围至少亮一档**。
3. 动态光源总数控制在 **8 个以内**，其余用自发光材质 + Lumen 拾取。
4. **关闭或锁定 Auto Exposure。** 明暗对比大的场景里，自动曝光是「画面忽明忽暗」的头号元凶。
5. 金色光路用 **Emissive 材质**，不必每个都配真实光源（Lumen 会拾取）。

### 5.8 渲染方案速查（UE 5.5）

| 项目 | 设置 |
| --- | --- |
| 全局光照 / 反射 | Lumen |
| 抗锯齿 | TSR |
| 阴影 | Virtual Shadow Maps |
| 曝光 | **Manual（手动锁定）** ★ |
| 后期 | Post Process Volume：Bloom 0.5~1.0 + 轻微暗角 |

**卡通化推荐组合（成本最低见效最快）：**

- **方案 A · 后处理描边**（⭐⭐⭐⭐⭐ 强烈推荐）：Post Process Material 用 SceneTexture:Depth 做边缘检测，边缘输出深色。**一两个小时就能做完，画面立刻「变成卡通」。**
- **方案 B · 卡通光照分级**：Master Material 用 `Floor`/`Step` 把光照分 2~3 级。（可选，做不出来只用 A 也够）

> ⚠️ **不要追求「完整 NPR」。** 你的目标是「看起来像卡通」，不是「复刻原神渲染管线」。
> **后处理描边 + 统一色板，已经能达到 80% 的观感。**

### 5.9 材质规范（统一风格的关键）

- **唯一的 Master Material 策略**：地板一套、建筑一套、发光体一套，共 **3 套 Master Material**，其余全部用**参数化实例**。
- **不要给每个道具做独立材质。** 新手最常见的浪费就在这里。
- 所有石材材质必须能调两个参数：**暗部色 / 亮部色**，且默认值就是本规范的冷灰绿。
- 自发光材质统一暴露 **发光颜色 + 强度** 两个参数，方便在蓝图上切换激活状态。

## 第二部分 · Tripo3D 工作流（本章重点）

### 5.11 为什么选 Tripo3D（决策确认）

你已确定：**本项目的大型建模全部交给 Tripo3D**。这个决定是合理的，因为它精准命中你的真实需求：**你要练的是 gameplay，不是雕花。**

Tripo3D 对本项目的价值：

| 能力 | 对本项目的意义 |
| --- | --- |
| 文字 → 3D | 直接输“中式浮空石台”就能出模型，不需要会画画 |
| 图片 → 3D | **最适合你**：用自己画的草图或搜到的参考图直接生成 |
| 多视角参考 | 给正/侧/背面图，模型准确度大幅提升 |
| 自动贴图 | 省掉 UV 展开 + 画贴图（新手最痛苦的两步） |
| 自动重拓扑 / 简面 | 直接导出低模，**避开了 AI 模型面数爆炸的致命问题** |
| 骨骼绑定 + 动画 | 可以生成简单角色动画（但角色主线仍建议 VRoid，见第四部分） |

> 💰 **预算提醒**：Tripo3D 有免费额度（每月复位），但**免费额度不够做完整个项目**。按你“预算基本控制在 token 内”的原则，建议策略是：
> **先把白盒跑通（M2–M8），确认不会大改了，再集中花额度生成美术资产。** 否则你会把额度浪费在会被推翻的东西上。
> 具体价格与额度以官网当前页面为准（它们变动较频），不要把本文档当价格表。

### 5.12 什么该用 Tripo3D，什么不该（重要）

这一节能替你省好几十小时：**AI 建模不是万能的，用错地方反而更麻烦。**

| 资产类型 | 用 Tripo3D？ | 原因 |
| --- | --- | --- |
| 浮空石台、巨石、山体、悬崖 | ✅ 最佳场景 | 有机形状，AI 擅长；碰撞另用简单体代替 |
| 圆形石拱门、牌坊 | ✅ 很适合 | 作为**地标**，本身不参与玩法逻辑 |
| 石灯、宝箱、石碑、供桌 | ✅ 很适合 | 单体道具，尺寸要求不严 |
| 远景碎石、树剪影、云雾体 | ✅ 最佳场景 | 本来就不需要精度 |
| 火元素方碑（门框造型） | 🟡 谨慎 | 是玩法对象，需要精确尺寸与插槽；生成后必须在 Blender 里修 |
| 旋转石柱（方柱机关） | ❌ 不推荐 | 需要**精确轴心**与 90° 对齐，AI 生成的不对称会让对齐永远判定不对 |
| 光桥 / 光路 | ❌ 不需要 | 本质是材质 + 简单几何体，在 UE 里做反而更快 |
| 台阶、栏杆、地砖等**需要拼接**的模块 | 🟡 不推荐 | 拼接件必须尺寸精确，建议 Blender 参数化生成（见第五部分） |
| 主角（类旅行者原创角色） | ❌ 不用 | 角色需要**可动画的标准骨骼**，用 VRoid（第四部分） |

> 🎯 **一句话记住**：**“长得奇怪也没关系的东西”交给 AI，“尺寸必须正确的东西”自己做。**

### 5.13 Tripo3D 实操流程（从提示词到进 UE）

**Step 1 · 生成（文生 3D 还是图生 3D？）**

- **图生 3D（推荐你用）**：先用 AI 画图工具或搜索找到一张风格对的参考图，再输入 Tripo。准确度高很多。
- **文生 3D**：适合“没有参考图、只要个大致形状”的远景物。
- **多视角（如果当前版本支持）**：三视图一起给，模型最准，适合建筑与方碑。

**Step 2 · 参数选择（生成前就要想清楚）**

| 选项 | 本项目建议值 | 原因 |
| --- | --- | --- |
| 面数 / 精细度 | 中低（低模化） | 你的画面靠**后期描边 + 统一色板**，不靠面数 |
| 贴图 | 生成后**丢掉，换成自己的卡通材质** | 否则风格不统一（第一部分已经说过） |
| 材质基调 | 不要直接用 | 见上 |

**Step 3 · 导出格式选择（关键）**

| 格式 | 本项目用途 | 注意 |
| --- | --- | --- |
| **FBX** | ✅ **进 UE 的首选** | 体积最大但兼容最好；骨骼/动画只能用它 |
| **GLB / glTF** | ✅ 次选 | 模型 + 材质 + 贴图打一个包，方便传输；UE 5.5 可导入 |
| OBJ | 🟡 备用 | 不带材质，仅纯几何体时用 |
| USDZ | ❌ 本项目不用 | 苹果生态格式 |

> ⚠️ **导出前先确认一件事**：导出时是否带了贴图。你要的是**只要模型形状**，贴图会被你丢掉重做，所以如果“无贴图导出”更快就选它。

**Step 4 · Blender 中转（可选，但强烈建议）**

花 10–20 分钟在 Blender 里做三件事，能避免 UE 里的一堆麻烦：

1. **重命名**为 `SM_LY_xxx`，并把轴心（Origin）对齐到底面中心
2. **检查尺寸**：用 Blender 的尺子量一下，确认它与你的白盒尺寸一致（比如石台直径 2.8 m）
3. **减面**（Decimate 修改器）：把面数压到 3000–8000 以内（道具）或 15000 以内（建筑）

**Step 5 · 导入 UE5 并修正常见问题**

见下一节的“6 个坑”。

**Step 6 · 登记 `AssetCredits.md`**

每导入一个 AI 生成资产，立刻在 `E:\UE_projects\LiuYun\Docs\AssetCredits.md` 里加一行（生成工具、日期、提示词、授权）。**这个习惯在面试时会直接加分。**

### 5.15 UE5 导入 Tripo3D 资产的 6 个坑

| 坑 | 症状 | 解决 |
| --- | --- | --- |
| **单位错位** | 模型变成至少数十倍大或小 | Tripo 导出以**米**为单位，UE 以**厘米**为单位。在 Blender 里先量好尺寸，导出 FBX 时保持默认转换，UE 导入时 Uniform Scale 用 `1.0`；导入后**放一个已知高度的参考物对比验证** |
| **坐标轴横躺** | 模型脸朝上 / 横卧 | Blender 是 Z-up，UE 是 Z-up 但 FBX 中间格式会换算。**导出 FBX 时勾选 `Apply Transform`** |
| **面数爆炸** | 单个石台 5万+ 面，帧率骤降 | Blender 加 `Decimate` 修改器；或 UE 导入时选 **生成简化版** |
| **材质风格不对** | 写实 PBR 贴图，与卡通风格冲突 | **丢掉 AI 贴图**，换上第一部分的 Master Material 卡通材质实例 |
| **没有碰撞** | 玩家直接穿模型掉下去 | 进 Static Mesh 编辑器 → Collision → **`Add Box Simplified Collision`**（浮空石台这种复杂形状用 Complex 会很吃帧） |
| **命名乱** | 导入后一堆 `mesh_001`，后期找不到 | 导入后**立刻重命名**为 `SM_LY_xxx`，放到 `Content/Art/` 对应子文件夹 |

> ⚠️ **最常见的一个错误**：把 AI 生成的高面数模型直接往关卡里摆。你的 4060 Laptop 跑不动。**导入前先减面，这是纪律，不是建议。**

### 5.20 中国风 / 仙侠素材的替代方案（重要）

**现实问题**：西方素材库里「中式仙侠建筑」很少。你要做的是璃月仙府，直接找现成素材会比较难。

**四种解法：**

1. **模块化拼装**：用「石材柱 + 石台 + 台阶 + 栏杆」这些**通用模块**拼出中式感觉。中式建筑的核心不是「雕花」，而是**比例、对称、层次**。
2. **配色出中国风**：冷灰绿石材 + 青碧天幕 + 金色纹样，**光靠配色就有 70% 的中国风**。
3. **AI 生成**：用 Meshy / Tripo 输入「Chinese xianxia floating stone platform, stylized, low poly」生成。
4. **细节靠材质**：中式纹样（云纹、回纹、几何刻纹）用**贴图/Decal** 而不是建模。找 CC0 的中式纹样黑图，或在 AI 生图工具里生成纹样贴图。

> 💡 **最有性价比的一招**：找 CC0 的**中式石灯笼**和**中式栏杆**，其他都用通用石材模块。这两个物件一放上去，中国风立刻成立。

**第 1 步：安装 VRoid Studio**
- 官网下载（免费），Windows 版。
- 安装后，选一个基础模型开始。

**第 2 步：捏角色（2～3 小时）**
- 调整脸型、发型、肤色、眼睛。
- **服装**：VRoid 自带一些服装，也可以导入别人做的（注意授权）。
- **配色**：让角色色板和场景协调（青碧 + 金 + 白）。
- 目标：**一个「仙侠风、长发、浅色衣服」的角色**即可，不需要像旅行者。

**第 3 步：导出 VRM**
- `File → Export → VRM`，保存为 `.vrm`。
- ⚠️ 注意导出时的**材质/贴图选项**，选「导出贴图」。

**第 4 步：导入 UE5**
两种方式：
- **方式 A（推荐）**：用 **VRM4U** 插件（免费，GitHub 上搜 `VRM4U`）。
  1. 下载插件，放到项目的 `Plugins/` 目录。
  2. 重新生成项目文件、编译。
  3. 直接把 `.vrm` 拖进 Content Browser。
- **方式 B**：用 Blender 中转（VRM → FBX → UE）。
  1. Blender 装 VRM 导入插件。
  2. 导入 VRM，导出 FBX（勾 `Apply Transform`，缩放注意）。
  3. 导入 UE。

**第 5 步：接动画**
- **Mixamo**：上传角色或直接用 Mixamo 预设角色，下载动画（Walking、Idle、Jumping 等）。
- ⚠️ Mixamo 的骨架和 VRM 骨架可能不匹配，需要**重定向（Retargeting）**。
- UE5 有 **IK Retargeter**，可以把 Mixamo 动画重定向到你的角色。

> ⚠️ **常见坑：缩放不对**。VRM 的单位是米，UE 是厘米。导入后角色可能是「巨人」或「蚂蚁」。
> **解决**：导入时检查 Scale（通常需要 ×100），或导入后在角色的 Skeletal Mesh 上调整。

## 🐛 常见坑

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 把 AI 生成的高面数模型直接摆进关卡 | 帧率骤降，780M/4060 都吃不消 | 导入前必须减面（3000–8000 面） |
| 直接用 AI 生成的写实贴图 | 与卡通画风严重冲突 | 丢掉贴图，用统一 Master Material |
| 提示词里写了“Genshin / 旅行者 / 钟离” | 直接触发侵权风险，面试减分 | 只用风格词，不用 IP 名 |
| 开工就把额度花在后期会改的资产上 | 额度浪费，白盒阶段无资产可用 | 先跑通白盒（M2–M8），再集中生成美术 |
| 每个道具做独立材质 | 数天浪费在材质上 | 3 套 Master Material + 参数化实例 |
| 把轴心没对齐的模型当旋转机关 | 旋转时满场乱飞 | 旋转件必须在 Blender 里把轴心对齐到旋转轴 |
