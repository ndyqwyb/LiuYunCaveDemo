### 4.2 先破除一个误解

**误解：「要么全 C++，要么全蓝图。」**

**真相**：两者不是竞争关系，是**分工关系**。

| 维度 | C++ | 蓝图 |
|---|---|---|
| 写复杂逻辑 | ✅ 强 | ❌ 节点连线会变成意大利面 |
| 性能 | ✅ 快 | 🟡 慢一点（本项目规模基本无所谓） |
| 迭代速度 | ❌ 改一次要编译 | ✅ 改完立刻看到 |
| 是否易上手 | ❌ 需要程序员 | ✅ 人人能用 |
| 调试 | 🟡 要断点 | ✅ 可视化调试，能看变量值 |
| 版本控制 | ✅ 纯文本，好合并 | ❌ 二进制，难合并 |
| 搜索引用 | ✅ 强 | 🟡 一般 |

### 4.3 核心心智模型：三层结构（把这张图刻在脑子里）

**任何一个游戏对象，都可以拆成三层：**

```
┌──────────────────────────────────────────────────────────┐
│  第 3 层：关卡中的实例（Level Instance）                  │
│  ── 在关卡里摆放的那个「具体的东西」                       │
│  ── 可以覆盖参数："这个风场上升速度 800，那个 600"        │
│  ── 可以替换引用："这个门用 A 材质，那个用 B 材质"          │
├──────────────────────────────────────────────────────────┤
│  第 2 层：蓝图子类（BP_ 资产）                             │
│  ── 继承自 C++ 类：BP_LY_WindField : ALY_WindField        │
│  ── 挂美术资源（网格体、粒子、音效）                       │
│  ── 摆组件、设默认值、做「一次性表现」逻辑                  │
├──────────────────────────────────────────────────────────┤
│  第 1 层：C++ 基类（A / U 类）                             │
│  ── ALY_WindField : AActor                                │
│  ── 定义「风场是什么」：属性、算法、状态机、对外接口        │
│  ── 不包含任何具体美术引用                                 │
│  ── 可被任意数量的蓝图子类继承                             │
└──────────────────────────────────────────────────────────┘
```

**一句话口诀（背下来）：**

> **C++ 定义「能力」和「规则」，蓝图定义「外观」和「数值」，关卡实例定义「这一处的特殊性」。**

### 4.4 判断标准：这个东西该写在哪？（决策流程）

遇到任何新功能，按这个顺序问自己：

```
开始
 │
 ├─ 这是一次性、只在某一处用的小逻辑吗？
 │   （例如：这扇门打开时播一个特定的音效）
 │   → YES：写在【蓝图事件图表】或【关卡蓝图】里
 │
 ├─ 这个功能需要重复使用 3 次以上吗？
 │   （例如：6 个机关都要「激活 → 发光 → 广播事件」）
 │   → YES：写【C++ 基类】，蓝图只做子类差异
 │
 ├─ 这个功能含复杂数学 / 循环 / 状态机吗？
 │   （例如：风场速度与柱顶判定、多开关组合逻辑、路径插值、谜题求解）
 │   → YES：【C++】
 │
 ├─ 这个功能只是「挂个粒子、设个材质、调个数」吗？
 │   → YES：【蓝图 / 细节面板】
 │
 └─ 拿不准？
     → 先用【蓝图】快速验证原型 → 验证成功后提取到 C++ → 蓝图改为继承 C++
```

> 💡 **对初学者最重要的建议：允许自己「先在蓝图里做一遍，再搬到 C++」。**
> 这不是浪费，这是**最快的学习路径**——你在蓝图里已经验证了逻辑是对的，搬到 C++ 只是「翻译」，心理压力小得多。原版很多商业项目也是这么做的。

### 4.5 具体分工对照表（建议打印贴在墙上）

| 内容 | 放哪 | 理由 |
|---|---|---|
| 风场的上升速度/柱顶判定 | **C++** | 状态量要反复调参和复用 |
| 风场的粒子特效引用 | **蓝图** | 纯资源引用 |
| 旋转桥的角度插值与对齐判定 | **C++** | 数学 |
| 旋转桥用哪段光路 | **蓝图 / 细节面板** | 资源引用 |
| 旋转桥的机械音效 | **蓝图** | 资源引用 |
| 火方碑「点亮」逻辑 + 事件广播 | **C++ 基类 + 蓝图子类** | 复用 + 变化 |
| 火方碑的火焰粒子 / 材质 | **蓝图** | 资源引用 |
| 记忆顺序谜题的状态机 | **C++** | 复杂逻辑、需要精确时序 |
| 谜题播放序列时的方碑提示特效 | **蓝图** | 表现层 |
| 联动翻转谜题的环索引算法 | **C++** | 数学，易错，需要单测 |
| 宝箱的开盖动画 | **蓝图**（Timeline） | 表现层 |
| 宝箱的解锁/开启状态 | **C++** | 逻辑 |
| 光路的「逐段点亮」 | **C++**（控制时机）+ **蓝图**（材质参数） | 逻辑 vs 表现 |
| 玩家输入绑定 | **C++**（Enhanced Input 绑定函数）+ **蓝图**（IMC 资产） | 逻辑 vs 资产 |
| 交互提示 UI 的显示 / 隐藏 | **C++ 触发 + Widget 蓝图** | 逻辑 vs 表现 |
| UI 的布局、字体、颜色 | **Widget 蓝图** | 纯表现 |
| 关卡阶段推进 | **C++**（GameFlowManager）+ **蓝图**配置 | 系统 |
| 检查点与重生 | **C++**（Subsystem / Manager） | 全局系统 |
| 过场镜头 | **Sequencer** | 专用工具 |
| 光照、后期、雾 | **在关卡里摆** | 表现 |

## 第三部分 · 反射宏与桥接机制（蓝图与 C++ 的“桥”）

### 4.9 必须掌握的 C++ 反射宏（蓝图与 C++ 的「桥」）

**这一节是你 C++ 入门的关键。** 反射宏决定了 C++ 的东西能否被蓝图看见、能否在编辑器里改。

```cpp
// 1. 声明一个类，让 UE 认识它
UCLASS(Blueprintable, BlueprintType)
class LIUYUN_API ALY_WindField : public AActor
{
    GENERATED_BODY()   // ★ 必须有，必须是类里第一行

public:
    ALY_WindField();

protected:
    // 2. 属性：编辑器可改，蓝图可读写
    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "LY|Wind")
    float RiseSpeed = 800.0f;

    // 3. 属性：只能在类默认值里改
    UPROPERTY(EditDefaultsOnly, Category = "LY|Wind")
    TObjectPtr<UStaticMeshComponent> MeshComp;

    // 4. 属性：蓝图只能看，不能改
    UPROPERTY(VisibleAnywhere, BlueprintReadOnly, Category = "LY|Wind")
    bool bIsActive = false;

    // 5. 函数：蓝图可以调用
    UFUNCTION(BlueprintCallable, Category = "LY|Wind")
    void ActivateWind();

    // 6. 函数：C++ 有默认实现，蓝图可以覆盖
    UFUNCTION(BlueprintNativeEvent, Category = "LY|Wind")
    void OnWindActivated();
    virtual void OnWindActivated_Implementation();   // ★ 注意 _Implementation 后缀

    // 7. 纯函数：蓝图可调用且无副作用
    UFUNCTION(BlueprintPure, Category = "LY|Wind")
    float GetStrength() const { return RiseSpeed; }

    // 8. 函数：C++ 不实现，完全交给蓝图填
    UFUNCTION(BlueprintImplementableEvent, Category = "LY|Wind")
    void PlayActivationEffects();
};
```

**关键区别（务必分清）：**

| 宏 | 含义 | 使用场景 |
|---|---|---|
| `BlueprintCallable` | 蓝图能调用这个函数 | 通用功能 |
| `BlueprintPure` | 同上，但是纯函数（无副作用） | Getter |
| `BlueprintImplementableEvent` | **C++ 不写实现**，完全交给蓝图 | 表现层（播特效、音效） |
| `BlueprintNativeEvent` | C++ 写默认实现，蓝图**可选**覆盖 | 有默认行为但允许定制 |
| `BlueprintReadWrite` / `BlueprintReadOnly` | 蓝图能否读写这个属性 | 属性暴露 |
| `BlueprintAssignable` | 蓝图可以绑定这个事件（委托） | 事件广播 |

**最常用的组合模式（背下来）：**

```cpp
// C++ 决定「什么时候」发生
void ALY_FirePillar::SetLit(bool bNewLit)
{
    bIsLit = bNewLit;
    OnLitChanged.Broadcast(bIsLit);   // 通知别人（蓝图/其他系统）
    PlayLitVisuals(bIsLit);           // ← 蓝图里接「换材质 + 播粒子 + 播音效」
}
```

> 这叫 **「C++ 管逻辑时机，蓝图管表现效果」**。
> **这一个模式能解决你 80% 的协作疑惑。**

### 4.10 其他必须知道的桥接机制

**① 委托 / 事件广播（让 C++ 通知蓝图，代替每帧轮询）**

```cpp
// 头文件里声明
DECLARE_DYNAMIC_MULTICAST_DELEGATE_TwoParams(FLY_OnMechanicStateChanged,
    AActor*, Mechanic, ELY_MechanicState, NewState);

UCLASS()
class ALY_MechanicBase : public AActor
{
    GENERATED_BODY()
public:
    UPROPERTY(BlueprintAssignable, Category = "LY|Events")
    FLY_OnMechanicStateChanged OnMechanicStateChanged;   // ★ 蓝图里能 Bind Event
};
```

**② 组件（把功能拆成可复用的零件）**

不要把所有逻辑都堆在 Actor 里。一个机关可以是：

```
BP_LY_FirePillar (Actor)
 ├── StaticMeshComponent        （外观：塔身）
 ├── NiagaraComponent           （火焰）
 ├── PointLightComponent        （红光）
 └── ULY_InteractComponent      （自制：统一的「可交互」能力）
```

自制组件 = 写一个 `ULY_InteractComponent : UActorComponent`，任何 Actor 挂上它就能交互。**这是 UE 最重要的复用手段。**

**③ 接口（Interface）——让不同东西以统一方式被「交互」**

```cpp
UINTERFACE(MinimalAPI, Blueprintable)
class ULY_Interactable : public UInterface { GENERATED_BODY() };

class LIUYUN_API ILY_Interactable
{
    GENERATED_BODY()
public:
    UFUNCTION(BlueprintNativeEvent, BlueprintCallable, Category = "LY|Interaction")
    bool CanInteract(AActor* Interactor) const;
    virtual bool CanInteract_Implementation(AActor* Interactor) const { return true; }

    UFUNCTION(BlueprintNativeEvent, BlueprintCallable, Category = "LY|Interaction")
    void Interact(AActor* Interactor);
    virtual void Interact_Implementation(AActor* Interactor) {}

    UFUNCTION(BlueprintNativeEvent, BlueprintCallable, Category = "LY|Interaction")
    FText GetInteractPrompt(AActor* Interactor) const;
    virtual FText GetInteractPrompt_Implementation(AActor* Interactor) const
    { return FText::FromString(TEXT("交互")); }
};
```

玩家只调用 `Interact()`，不关心对方是拉杆、宝箱还是门。**这是「面向接口」思想的落地，面试时是很重要的加分点。**

**④ 数据资产 / 数据表（把「数值」从代码里拿出来）**

```cpp
UCLASS(BlueprintType)
class ULY_PuzzleConfigDataAsset : public UPrimaryDataAsset
{
    GENERATED_BODY()
public:
    UPROPERTY(EditAnywhere, Category = "LY|Puzzle")
    TArray<int32> RoundLengths = { 3, 4, 5 };

    UPROPERTY(EditAnywhere, Category = "LY|Puzzle")
    float FlashDuration = 0.6f;

    UPROPERTY(EditAnywhere, Category = "LY|Puzzle")
    float GapDuration = 0.3f;
};
```

好处：调数值不用编译 C++、不用改蓝图，做一个 `.uasset` 就能配。**面试官特别想看到这个。**

**⑤ Subsystem（全局系统，UE5 推荐）**

`UGameInstanceSubsystem` / `UWorldSubsystem` 适合放「存档、检查点、关卡流程、成就」这类全局状态。比塞进 GameMode 更干净，也更现代。

**⑥ Enhanced Input（UE5 输入系统）**

- **C++**：写 `SetupPlayerInputComponent`，绑定 `UInputAction*` 到处理函数
- **蓝图**：创建 `IMC_LY_Default`（Input Mapping Context）和各个 `IA_*`（Input Action）资产
- 分工：**C++ 管逻辑，蓝图管资产**

### 4.11 三条铁律（违反会痛不欲生）

**铁律 1：永远不要让蓝图「重新指定父类」，除非你做好资产损坏的心理准备。**
如果你已经做了一堆 `BP_LY_FirePillar`，然后想把 C++ 父类改名或换继承链——会触发资产重定向/损坏。**先在 C++ 里把设计稳定下来，再让蓝图继承。**

**铁律 2：C++ 改了 `UPROPERTY` 的名字 = 蓝图里已设置的数值可能丢失。**
改名时 UE 通常能弹窗问你要不要保留引用，**一定选保留**。更稳的做法：尽量不改已发布属性的名字；要改就一次性在早期改完。

**铁律 3：不要在编辑器运行中用 Live Coding 编译「复杂结构变更」。**
Live Coding（`Ctrl+Alt+F11`）只能热补丁**函数体**。改头文件、加属性、加类，必须**关掉编辑器 → 用 IDE 重新编译 → 重开编辑器**。
习惯：小改函数体 → Live Coding 可以；改 `.h`、加类、加属性 → **关编辑器重新 Build**。

### 4.12 初学者最常见的 6 个协作错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 在蓝图里重新实现 C++ 已有的逻辑 | 两套逻辑打架，行为诡异 | C++ 写一遍，蓝图只做差异 |
| C++ 类里直接引用具体 `BP_xxx` 资产 | 循环依赖、编译不过 | C++ 只声明基类指针 / Component，资产由蓝图指定 |
| 把所有逻辑塞进关卡蓝图 | 无法复用、无法调试、无法版本控制 | 提取成 Actor / Component |
| 蓝图函数参数硬 Cast 成具体类 | 一改就崩 | 用接口 + 基类 |
| C++ 属性忘了加 `UPROPERTY` | 被 GC 回收 → 随机崩溃 | 所有 UObject 指针成员必须 `UPROPERTY` |
| 在 C++ 构造函数里做需要世界存在的操作 | 崩 | 构造里只建组件 / 设默认值；世界操作放 `BeginPlay` |

### 4.13 你项目的「默认技术决策」（照抄即可，不用纠结）

1. 所有**机关** → 一个 C++ 基类 `ALY_MechanicBase`，一个蓝图子类
2. 所有**可交互物** → 实现 `ILY_Interactable` 接口
3. 所有**需要广播的事件** → 用 `DECLARE_DYNAMIC_MULTICAST_DELEGATE`
4. 所有**表现**（特效、音效、动画）→ `BlueprintImplementableEvent`
5. 所有**可调数值** → `UPROPERTY(EditAnywhere)` 或 DataAsset
6. 所有**全局状态** → GameInstance Subsystem
7. 所有**输入** → Enhanced Input（C++ 绑定函数，蓝图配 IMC）
8. 所有**UI 触发逻辑** → C++ 调用，Widget 蓝图负责显示

#### 4.15.2 蓝图如何实现这个接口

1. 蓝图类 → Class Settings → Interfaces → Add → `LY Interactable`。
2. 在蓝图里会出现三个事件： `Can Interact`、 `Interact`、 `Get Interact Prompt`。

### 4.16 机关基类 `ALY_MechanicBase`

```cpp
// LY_MechanicBase.h
#pragma once
#include "CoreMinimal.h"
#include "GameFramework/Actor.h"
#include "Core/LY_Types.h"
#include "Mechanics/LY_Interactable.h"
#include "LY_MechanicBase.generated.h"

DECLARE_DYNAMIC_MULTICAST_DELEGATE_TwoParams(
    FLY_OnMechanicStateChanged, ALY_MechanicBase*, Mechanic, ELY_MechanicState, NewState);

/**
 * 所有机关的公共父类。

UCLASS(Abstract, Blueprintable)
class LIUYUN_API ALY_MechanicBase : public AActor, public ILY_Interactable

    UPROPERTY(EditAnywhere, BlueprintReadOnly, Category = "LY|Mechanic")
    ELY_MechanicState InitialState = ELY_MechanicState::Available;

    /** 是否只能激活一次 */
    UPROPERTY(EditAnywhere, BlueprintReadOnly, Category = "LY|Mechanic")
    bool bOneShot = true;

    /** 交互提示文字 */
    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "LY|Mechanic")
    FText InteractPrompt = NSLOCTEXT("LY", "DefaultMechanicPrompt", "按 E 交互");

    UPROPERTY(VisibleAnywhere, BlueprintReadOnly, Category = "LY|Mechanic")
    ELY_MechanicState MechanicState = ELY_MechanicState::Dormant;

```

#### 4.16.1 实现要点

```cpp
// LY_MechanicBase.cpp
#include "Mechanics/LY_MechanicBase.h"

ALY_MechanicBase::ALY_MechanicBase()
{
    PrimaryActorTick.bCanEverTick = false;   // ★ 机关默认不需要 Tick
    bReplicates = false;
}

void ALY_MechanicBase::BeginPlay()
{
    Super::BeginPlay();
    SetMechanicState(InitialState);
}

void ALY_MechanicBase::SetMechanicState(ELY_MechanicState NewState)
{
    if (MechanicState == NewState) return;

    // 一次性机关：Completed 之后不能再变
    if (bOneShot && MechanicState == ELY_MechanicState::Completed) return;

    MechanicState = NewState;

    // ★ 先广播（逻辑层监听），再调表现（美术层）
    OnMechanicStateChanged.Broadcast(this, NewState);
    OnStateChangedVisuals(NewState);
}

bool ALY_MechanicBase::CanInteract_Implementation(AActor* Interactor) const
{
    return MechanicState == ELY_MechanicState::Available;
}

void ALY_MechanicBase::Interact_Implementation(AActor* Interactor)
{
    SetActive();   // 子类通常重写
}

FText ALY_MechanicBase::GetInteractPrompt_Implementation(AActor* Interactor) const
{
    return InteractPrompt;
}
```

**三条纪律**：
1. **`bCanEverTick = false`**：机关不需要每帧更新，需要定时用 Timer。
2. **先 `Broadcast` 再 `OnStateChangedVisuals`**：保证逻辑先于表现。
3. **表现层永远不决定状态**： `OnStateChangedVisuals` 只读状态，不改状态。

### 4.18 旋转光桥 `ALY_RotatingBridge`（含角度对齐）

> ⚠️ 本节代码是**最小骨架**。已定方案（转盘上**左右两个按钮**、石路残段、180°/90° 两种预置）以 `03_机关设计规格.md` 的 `3.3` / `3.14` 为准。

```cpp
// LY_RotatingBridge.h
#pragma once

#include "Mechanics/LY_MechanicBase.h"

DECLARE_DYNAMIC_MULTICAST_DELEGATE_OneParam(FLY_OnRotationFinished, int32, StepIndex);

    virtual bool CanInteract_Implementation(AActor* Interactor) const override;

protected:
    UPROPERTY(VisibleAnywhere, BlueprintReadOnly, Category = "LY|RotatingBridge")
    int32 StepIndex = 0;

    UPROPERTY(VisibleAnywhere, BlueprintReadOnly, Category = "LY|RotatingBridge")
```

```cpp
// LY_RotatingBridge.cpp
#include "Mechanics/LY_RotatingBridge.h"
#include "TimerManager.h"

ALY_RotatingBridge::ALY_RotatingBridge()
{
    InteractPrompt = NSLOCTEXT("LY", "RotatePrompt", "按 E 旋转");
}

bool ALY_RotatingBridge::CanInteract_Implementation(AActor* Interactor) const
{
    // ★ 旋转中不能交互（防止角度错乱）
    return Super::CanInteract_Implementation(Interactor) && !bIsRotating;
}

void ALY_RotatingBridge::Interact_Implementation(AActor* Interactor)
{
    if (bIsRotating) return;

    bIsRotating = true;

    const float FromAngle = StepIndex * StepAngle;
    StepIndex = (StepIndex + 1) % 4;                 // ★ 取模，0-1-2-3 循环
    const float ToAngle = StepIndex * StepAngle;

    OnRotateVisuals(FromAngle, ToAngle, RotateDuration);

    GetWorldTimerManager().SetTimer(
        RotateTimer, this, &ALY_RotatingBridge::FinishRotation,
        RotateDuration, false);
}

void ALY_RotatingBridge::FinishRotation()
{
    bIsRotating = false;

    const bool bAlignedNow = IsAligned();
    OnAlignedChanged(bAlignedNow);

    if (bAlignedNow)
    {
        SetMechanicState(ELY_MechanicState::Completed);
    }

    OnRotationFinished.Broadcast(StepIndex);
}
```

> 💡 **注意：这里用「步进计数」而不是「浮点角度比较」，这是最稳的做法。**
> 因为每次旋转都是固定 90°，把「转了几次」记为整数，判定永远是 `StepIndex == TargetStep`，**完全避开了浮点误差**。
> **`09_风险与踩坑速查.md` 坑 31 给的 `FindDeltaAngleDegrees` 方案，适用于「玩家能自由旋转任意角度」的情况。本项目因为是固定 90° 步进，用整数计数更简单、更可靠。**

**如果一定要用角度比较（自由旋转场景）：**
```cpp
const float Delta = FMath::Abs(FMath::FindDeltaAngleDegrees(CurrentAngle, TargetAngle));
if (Delta < 5.0f) { /* 对齐 */ }
```

**蓝图 `BP_LY_RotatingBridge` 实现 `OnRotateVisuals`：**
1. 用 **Timeline**（0→1，时长 = Duration）驱动 `SetRelativeRotation`。
2. `Lerp` 的起始值是 `FromAngle`，终点是 `ToAngle`。
3. ⚠️ **旋转的是「石柱」组件，不是整个 Actor**（除非你只想转整个物体）。

```cpp
    /** 被方碑回调（方碑点亮时把自己的 MechIndex 上报） */
    UFUNCTION()
    void HandlePillarLit(ALY_FirePillar* Pillar);

protected:
    virtual void BeginPlay() override;

    int32 CurrentRound = 0;
    int32 InputIndex = 0;
    bool bShowingSequence = false;

    void ShowCurrentRound();
    void CompleteRound();
    void FailRound();
};
```

**实现要点（伪代码）：**
```
StartPuzzle():
    订阅所有 Pillars 的 OnPillarLitChanged 事件
    CurrentRound = 0
    ShowCurrentRound()

ShowCurrentRound():
    bShowingSequence = true
    熄灭所有方碑
    对第 CurrentRound 轮的 Sequence 里每个 MechIndex：
        OnShowSequenceStep(MechIndex, Interval)   // 蓝图延时点亮
        等待 Interval
    bShowingSequence = false
    InputIndex = 0
    允许玩家输入

HandlePillarLit(Pillar):
    if bShowingSequence: return          // 展示时忽略输入
    Expected = Rounds[CurrentRound].Sequence[InputIndex]
    if Pillar->MechIndex == Expected:
        InputIndex++
        if InputIndex == Sequence.Num(): CompleteRound()
    else:
        FailRound()

CompleteRound():
    OnRoundFeedback(true)
    CurrentRound++
    if CurrentRound >= Rounds.Num():
        OnPuzzleStateChanged.Broadcast(this, Completed)   // 三轮完成：三个宝箱均已解锁
        // 风场不在这里开启 → 由 GameFlowManager 在「三个宝箱全部打开」时开启（见 3.6）
    else:
        延时 1 秒后 ShowCurrentRound()

FailRound():
    OnRoundFeedback(false)
    延时 0.8 秒后 ShowCurrentRound()      // 重新展示本轮
```

> ⚠️ **核心难点：时序**。展示序列时玩家输入必须被忽略（`bShowingSequence`）。**先让「播放」跑通，再加「校验」。**
> ⚠️ **不要用 Tick 做延时**，用 `FTimerHandle` 或蓝图的 Delay 节点。
> 💡 **为什么把「展示」放到蓝图（`OnShowSequenceStep`）**：因为点亮表现的节奏、音效、粒子是美术向的，放在蓝图里可以随时调。

### 4.20 联动翻转谜题 `ULY_ToggleRingPuzzleComponent`

这是**纯逻辑算法**，非常适合放 C++。

```cpp
// LY_ToggleRingPuzzleComponent.h
#pragma once
#include "CoreMinimal.h"
#include "Components/ActorComponent.h"
#include "LY_ToggleRingPuzzleComponent.generated.h"

class ALY_FirePillar;

DECLARE_DYNAMIC_MULTICAST_DELEGATE_OneParam(FLY_OnRingSolved, bool, bSolved);

/**
 * 环形联动翻转谜题：
 * 点击第 i 个柱子 → 翻转 i-1、i、i+1（环形）。
 * 全部点亮 = 解开。
 */
UCLASS(ClassGroup=(LY), meta=(BlueprintSpawnableComponent))
class LIUYUN_API ULY_ToggleRingPuzzleComponent : public UActorComponent
{
    GENERATED_BODY()

public:
    ULY_ToggleRingPuzzleComponent();

    /** 环上的柱子，顺序 = 环的顺序（关卡里按顺时针拖入） */
    UPROPERTY(EditInstanceOnly, BlueprintReadOnly, Category = "LY|Puzzle")
    TArray<ALY_FirePillar*> RingPillars;

    UPROPERTY(BlueprintAssignable, Category = "LY|Puzzle")
    FLY_OnRingSolved OnRingSolved;

    /** 玩家点了第 Index 个柱子 */
    UFUNCTION(BlueprintCallable, Category = "LY|Puzzle")
    void HandlePillarClicked(int32 Index);

    /** 重置到初始状态 */
    UFUNCTION(BlueprintCallable, Category = "LY|Puzzle")
    void ResetRing();

    UFUNCTION(BlueprintPure, Category = "LY|Puzzle")
    bool IsSolved() const;

protected:
    virtual void BeginPlay() override;

    /** 初始点亮状态（空 = 全灭） */
    UPROPERTY(EditAnywhere, BlueprintReadOnly, Category = "LY|Puzzle")
    TArray<bool> InitialStates;

    /** 取模索引：环形安全 */
    int32 WrapIndex(int32 Index) const
    {
        const int32 N = RingPillars.Num();
        if (N <= 0) return 0;
        return ((Index % N) + N) % N;      // ★ 处理负数
    }
};
```

```cpp
// LY_ToggleRingPuzzleComponent.cpp
#include "Puzzles/LY_ToggleRingPuzzleComponent.h"
#include "Mechanics/LY_FirePillar.h"

void ULY_ToggleRingPuzzleComponent::HandlePillarClicked(int32 Index)
{
    const int32 N = RingPillars.Num();
    if (N <= 0 || !RingPillars.IsValidIndex(Index)) return;

    // 翻转自己 + 左右相邻（环形）
    const int32 Left  = WrapIndex(Index - 1);
    const int32 Right = WrapIndex(Index + 1);

    RingPillars[Left ]->SetLit(!RingPillars[Left ]->IsLit());
    RingPillars[Index]->SetLit(!RingPillars[Index]->IsLit());
    RingPillars[Right]->SetLit(!RingPillars[Right]->IsLit());

    OnRingSolved.Broadcast(IsSolved());
}

bool ULY_ToggleRingPuzzleComponent::IsSolved() const
{
    for (const ALY_FirePillar* P : RingPillars)
    {
        if (!P || !P->IsLit()) return false;
    }
    return RingPillars.Num() > 0;
}
```

> ⚠️ **`WrapIndex` 必须处理负数**： `(-1) % 6` 在 C++ 里等于 `-1`，不是 `5`！这是新手必踩的坑。
> ✅ 正确写法： `((Index % N) + N) % N`。
> 💡 **写代码前先在纸上验证谜题有解。** 本项目建议初始状态设为「三灭三亮」或「全灭」这种有明确解法的状态。

### 4.21 风场 `ALY_WindField`

### B. 角色侧（改 CMC 参数 + 每帧写速度）

```cpp
// LY_PlayerCharacter.h（片段）
/** 0 = 不在风场；1 = 在风场内 */
UPROPERTY(BlueprintReadOnly, Category = "LY|Wind")
bool bIsInWindField = false;

UPROPERTY()
TWeakObjectPtr<ALY_WindField> CurrentWindField;

void EnterWindField(ALY_WindField* Field);
void ExitWindField();

private:
    void ApplyWind(float DeltaSeconds);

    // 进入风场前的原始值，出柱时逐个还原
    float SavedGravityScale = 1.f;
    float SavedAirControl = 0.05f;
    float SavedBrakingDecelerationFalling = 0.f;
```

```cpp
void ALY_PlayerCharacter::EnterWindField(ALY_WindField* Field)
{
    if (!Field || bIsInWindField) return;

    UCharacterMovementComponent* M = GetCharacterMovement();
    SavedGravityScale = M->GravityScale;
    SavedAirControl = M->AirControl;
    SavedBrakingDecelerationFalling = M->BrakingDecelerationFalling;

    M->GravityScale = 0.f;                    // ★ 零重力
    M->AirControl = 1.f;                      // ★ 不调到 1，柱内按 W 几乎不动
    M->BrakingDecelerationFalling = 1200.f;   // 松手能停住

    // 从坠落冲进柱子时不要"啪"一下，0.2 秒把 Z 速度拉到 RiseSpeed
    M->Velocity.Z = FMath::FInterpTo(M->Velocity.Z, Field->RiseSpeed, 0.2f, 10.f);

    CurrentWindField = Field;
    bIsInWindField = true;
}

void ALY_PlayerCharacter::ApplyWind(float DeltaSeconds)
{
    if (!bIsInWindField) return;
    ALY_WindField* Field = CurrentWindField.Get();
    if (!Field) { ExitWindField(); return; }

    UCharacterMovementComponent* M = GetCharacterMovement();
    const float CeilingZ = Field->GetCeilingWorldZ();
    const float Tol = Field->CeilingTolerance;

    if (GetActorLocation().Z < CeilingZ - Tol)
    {
        // ① 上升段：每帧直接写，匀速。不用 AddForce、不用加速度累加
        M->Velocity.Z = Field->RiseSpeed;
    }
    else
    {
        // ② 悬停段：零重力 + Z 速度为 0 → 玩家只能动 XY
        M->Velocity.Z = 0.f;

        // ③ 可选保险：默认关闭。开启后给一点点朝目标平台的水平插值
        if (Field->bTopPushEnabled)
        {
            if (AActor* Target = Field->LandingTarget.Get())
            {
                const FVector Dir =
                    (Target->GetActorLocation() - GetActorLocation()).GetSafeNormal2D();
                M->Velocity.X = FMath::FInterpTo(M->Velocity.X, Dir.X * Field->TopPushSpeed, DeltaSeconds, 6.f);
                M->Velocity.Y = FMath::FInterpTo(M->Velocity.Y, Dir.Y * Field->TopPushSpeed, DeltaSeconds, 6.f);
            }
        }
    }
}

void ALY_PlayerCharacter::ExitWindField()
{
    if (!bIsInWindField) return;

    UCharacterMovementComponent* M = GetCharacterMovement();
    M->GravityScale = SavedGravityScale;                             // ★ 还原重力
    M->AirControl = SavedAirControl;
    M->BrakingDecelerationFalling = SavedBrakingDecelerationFalling;

    bIsInWindField = false;
    CurrentWindField = nullptr;
    // 之后就是普通自由落体：按住 W 即可落到 ⑧ 号岛
}
```

在角色 Tick 里调用（`Tick` 里只做这一件事）：
```cpp
void ALY_PlayerCharacter::Tick(float DeltaSeconds)
{
    Super::Tick(DeltaSeconds);
    ApplyWind(DeltaSeconds);
}
```

**两个必须注意的点：**
1. **`bIsInWindField` 用来驱动动画蓝图**——`WindRise` / `WindHover` 两个状态读这个布尔，进出各设一次。因为它只在这两个函数里变化，所以不会每帧抖动。
2. **风场体积绝不能与 ⑧ 号岛的可行走面重叠**：重叠会让 E 边缘变成「踩上去就飘」的怪区域。**接壤（间隙 0～100 uu）是安全的。**

> 🎮 **操作说明（写进游戏内提示）**：「升到顶端后，朝前方平台按住 W 飞出去。」
> 玩家在悬停状态下出柱时**竖直速度为 0**（不是下坠中），从柱顶（E 地面 + 450）自由落体，横向 300～400 uu/s 时落点在 ⑧ 号岛边缘内 287～383 uu —— **⑧ 号岛直径 2000 uu，余量充足，不需要横向助推。**

## 🐛 常见坑

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 把行为逻辑全写进关卡蓝图 | 无法复用，改一处要改十处，面试减分 | 逻辑写进 `ALY_MechanicBase` 子类，关卡只摆 Actor |
| 在 C++ 构造函数里读其他 Actor | 加载时间错位、空指针崩溃 | 改用 `BeginPlay` 或 `PostInitializeComponents` |
| 头文件里 `#include "Blueprint/UserWidget.h"` 并持有指针 | 编译超慢、环循依赖、打包可能失败 | 用 `TSubclassOf<UUserWidget>` + 前向声明 |
| 把 `UPROPERTY` 忘了 | 对象被 GC 回收，随机崩溃 | 所有 `UObject*` 成员都要 `UPROPERTY()` |
| 在蓝图里重写了 C++ 的 `Tick` 逻辑 | 两套逻辑冲突，难 bug | 蓝图只做表现，逻辑在 C++ 一处 |
| 改了头文件只点“编译”按钮 | Live Coding 不支持，行为奇怪 | 改头文件必须关编辑器，用 VS 重新 Build |
| 把 `Content/ThirdPerson/` 模板内容当成自己的 | 提交里混淆，面试官分不清哪些是你写的 | 自制内容全放 `Content/` 下自建文件夹（扁平结构），模板内容只读不改 |
| 没有及时提交 | 改坏无法回退，进度归零 | 每完成一个小功能就提交一次 |
