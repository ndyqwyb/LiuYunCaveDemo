# 01 · 项目定位、版权合规与范围

> 本章回答三件事：**这个项目是什么**、**什么绝对不能碰**、**要做什么 / 不做什么**。
> 开工前必须读完，这三件事决定了后面所有决策的方向。

---

## 一、项目定位

### 1.1 这是作品集项目，不是商业项目

你的目的是投米哈游等游戏公司的**实习 / 校招**。所以做每一个决策时，永远问一句：

> **「招聘方看这段代码 / 这个视频，能不能看出我会做 gameplay？」**

| 能加分 | 不加分（别投入） |
|---|---|
| 机关状态机、数据驱动配置 | 模型面数高、贴图 4K |
| 可复用的组件与基类设计 | 场景里塞 200 个装饰道具 |
| 清晰的关卡节奏与引导 | 战斗手感、数值平衡 |
| 能跑通、有演示视频、有 DevLog | 滑翔、攀爬、大世界 |

**结论：把 90% 时间花在「玩法系统 + 关卡节奏」，10% 花在「让它看起来像那么回事」。**

### 1.2 招聘方实际想看什么（按重要度）

1. **能跑通的完整流程** —— 进入关卡到结算，不卡死不穿帮
2. **系统抽象能力** —— 机关有没有抽象成可复用基类，而不是 6 个各写一遍的蓝图
3. **数据驱动意识** —— 谜题序列、宝箱奖励放在 DataAsset / DataTable，而不是硬编码
4. **C++ 与蓝图的边界感** —— 这是你最大的疑惑，见 `04_蓝图与C++协作.md`
5. **关卡设计意图** —— 为什么这样引导玩家？节奏与难度曲线怎么设计？
6. **工程规范** —— 目录结构、命名、Git 记录、README

### 1.3 三个体验支柱（设计时随时回看）

| 支柱 | 含义 | 落到实现 |
|---|---|---|
| **看得见的路** | 玩家永远知道下一步去哪 | 金色光路 + 远处发光目标 + 光照对比 |
| **懂了就会** | 规则简单、反馈即时、允许试错 | 3 秒内给反馈；做错能重来；不做一命通关谜题 |
| **一层层打开** | 每次解谜，空间打开一层 | 解谜 → 光路亮 → 新区域可达 → 新谜题 |

### 1.4 成功标准（可度量）

- [ ] 陌生人能在不看说明的情况下 **15 分钟内通关**
- [ ] 6 种机关都能单独拖进空关卡并正常工作（**可复用性证明**）
- [ ] 改一个 DataAsset 就能改变谜题配置（**数据驱动证明**）
- [ ] Git 仓库有 100+ 次有意义的提交，提交信息可读
- [ ] 一段 3～5 分钟视频，能讲清「我做了什么、怎么做的、为什么这么做」

## 二、版权与合规（唯一会「毁掉整个作品集」的风险）

### 2.1 事实层面

- 米哈游官方**允许**非商业性同人二创，各游戏都发布过《同人创作指引》，允许对已公开发表内容进行二次创作（文字、图片、视频、实物等），前提是不得损害品牌形象、不得注册商标或做著作权登记。
- 但指引同时明确：**米哈游依法享有游戏 IP 的著作权，涵盖角色形象、美术原画、3D 模型、音乐、文案等。**
- 官方周边指引有一条很关键：**「直接使用」「描改」「局部改动」官方素材用作同人实体周边或商品详情页素材，是不被允许的。**

### 2.2 决策对照表

| 做法 | 风险 | 结论 |
|---|---|---|
| 自己从零搭一个「类留云借风洞天」的关卡 | 低（玩法/关卡结构不受著作权保护） | ✅ 推荐 |
| 从原神客户端提取模型/贴图/音频直接用 | **高** | ❌ 不要 |
| 从 GitHub / 网盘下载别人提取的原神模型 | **高**（还无法确认来源合法性） | ❌ 不要 |
| 用 AI 生成原创的「类原神风格」角色和建筑 | 低 | ✅ 推荐 |
| 用 Sketchfab / Fab 上 CC 授权的**粉丝自制**模型 | 中（原作者本身可能侵权） | ⚠️ 逐项登记 |
| 用官方名称、台词、剧情文本 | 低～中（引用范畴） | ⚠️ 可少量使用，别大段照搬 |

### 2.3 ⭐ 关键：你要投的是米哈游

这带来一个微妙但重要的判断：

- **面试官大概率不会因为「你复刻了自家游戏关卡」反感** —— 反而会觉得你做足功课、真心喜欢这个 IP。
- 但**面试官一定在意你是否清楚版权边界。** 一个说「我从客户端扒了模型」的候选人，会被打上「工程规范存疑」标签。
- **最加分的表述**：「我用原创的、类原神风格的素材重建了这个关卡，因为我不想在作品集里使用未经授权的官方资产。」

所以：**主动做正确的事，并在 README / 视频里说明你做了正确的事。这本身就是一个展示职业素养的加分点。**

### 2.4 角色方案决策

| 方案 | 描述 | 版权 | 美术成本 | 推荐度 |
|---|---|---|---|---|
| **A. 原创角色（推荐）** | VRoid Studio 捏一个「类原神风格的原创少年/少女」 | ✅ 干净 | 低 | ⭐⭐⭐⭐⭐ |
| B. 免费 CC 授权动漫角色 | Sketchfab 明确 CC-BY / CC0 | ⚠️ 中 | 极低 | ⭐⭐⭐ |
| C. 直接使用旅行者模型 | 提取工具或网盘 | ❌ 高 | 极低 | ❌ 不做 |

**走 A。** 理由：

1. 你的目标是练 gameplay，角色外观对玩法无影响。
2. 面试时可直接说「这个角色是我原创/AI 生成的」，**零风险，还展示了 AI 工具链能力**。
3. 想保留「旅行者」感觉：可以做「金发、披风、剑、冒险者气质」的**原创**角色 —— **神韵像，但不是同一个形象**。

> ⚠️ **如果你坚持用官方旅行者模型**：只在本地私有场合使用，作品集视频里绝不出现，绝不打包进公开仓库。**仍然强烈不建议。**

## 四、范围与取舍（档位 B）

### 4.1 档位 B 的确切定义

- **关卡范围**：完整复刻洞府内部主线流程（8 个流程阶段 / 11 个节点）；奥藏山前置最多做 P2 简化版。
- **美术标准**：低模 + 卡通着色 + 统一色板，目标是「风格统一、不难看」，不是「像原神」。
- **系统标准**：机关可复用、配置数据驱动、流程完整可通关。
- **交付标准**：能打包成 exe、有片头到结算的完整流程、有 3～5 分钟演示视频。

### 4.2 优先级清单（可直接当任务表）

**P0 · 不做就没法通关**

1. 第三人称角色：移动 + 跳跃 + 交互（**不含滑翔、不含战斗**）
2. 交互系统：接近检测 + 交互提示 + 交互接口
3. **旋转光桥机关**（全关卡出现 3 次，灵魂机关）
4. **联动翻转火柱谜题**（六柱全亮 → 开路）
5. 浮空平台 + 金色光路的关卡结构（至少 5 座平台）
6. 火方碑点燃（点火 → 触发 → 反馈）
7. 风场上升气流（**电梯式**，不需要滑翔）
8. 宝箱 3 个（对应阶段 3 三轮解密）
9. 关卡流程管理（阶段推进、通路开关、通关判定）
10. 基础 HUD：目标提示 + 交互提示 + 掉落后重生

**P1 · 做了才像完整游戏**

11. **记忆顺序火柱谜题**（三轮递增，阶段 3）
12. 光路亮起/熄灭的视觉过渡（材质参数动画）
13. 终点庭院 + 留云 NPC + 对话/字幕系统
14. 结算界面（用时 + 宝箱数）
15. 环境音 + 机关音效
16. 检查点与掉出地图重生
17. 简易设置菜单

**P2 · 有余力再说**

18. 奥藏山前置简化版（三石椅 + 三供奉点，不做烹饪）
19. 移动平台
20. 仙鹤/白鹭等动态装饰
21. 存档 / 读档
22. 滑翔（**默认不做**）

**明确不做**

- ❌ 任何战斗（史莱姆、丘丘人、元素反应、伤害、血量）
- ❌ 滑翔翼飞行 → 风场改为**垂直气流电梯**
- ❌ 烹饪小游戏
- ❌ 抽卡 / 属性 / 装备 / 等级 / 元素反应
- ❌ 多人联机
- ❌ 大世界、攀爬、游泳、体力条
- ❌ 从原神客户端提取的任何资产

### 4.3 关于滑翔的正式决策

**结论：不做滑翔。**

- 滑翔要处理空中控制、体力、落地判定、动画、镜头跟随，是**独立系统级**工作量。
- 本 Demo 玩法支柱是「机关解密」，风场的作用只是**空间搬运**，垂直上升气流 + 顶部平台即可达成同样的关卡功能。
- 面试官看的是「你有没有把机关做透」，不是「有没有滑翔」。

> 若日后想加：等 P0+P1 全部完成、打包稳定后，作为独立实验加，**不阻塞主线**。

### 4.4 三条「防膨胀」规则（贴在显示器上）

1. **新点子先扔进 P2 清单**，不要立刻做。等当前里程碑收尾再统一评估。
2. **任何功能，先用蓝图通 1 个版本就够**，确认关卡需要它，再考虑 C++ 化。
3. **每周必须有一次「可通关」的状态**。哪怕很丑，也必须能从入口走到终点。

## 🐛 常见坑

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 先花 3 个月学理论 | 项目永远不开始 | 按需学习，边做边学 |
| 「反正不商用」就用官方模型 | 作品集被打上侵权标签 | 原创角色 + AI 素材 |
| 中途加战斗 / 滑翔 | 范围膨胀，主线延期 | 新点子一律进 P2 |
| 追求「像原神」的美术 | 美术工期失控 | 目标是「风格统一、不难看」 |
