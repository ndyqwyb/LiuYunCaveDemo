# 09 · 风险与踩坑速查

> 本章是“安全气囊”。不需要背下来，但**卡住的时候一定要回来翻**。
> 风险按危险程度排序：🔴 = 会让项目死掉，必须提前防；🟠 = 会浪费大量时间；🟡 = 会烦但可控。

### 9.2 「卡住了怎么办」——标准排查流程

**按顺序执行，不要跳步，尤其不要「乱试」。**

#### 9.2.1 第 1 步：看 Output Log（不要瞎猜）

- 编辑器里打开 **Window → Output Log**。
- 找 **红色的 Error**（不是 Warning）。
- **复制完整的报错原文**，包括：
  - 报错类型（error C2039 / LNK2019 / Assertion failed…）
  - 文件名和行号
  - 最后几行堆栈

> ⚠️ **90% 的信息都在报错文本里。** 新手最常见的错误是「不看报错，直接改代码，改来改去更乱」。

#### 9.2.2 第 2 步：搜报错

把**报错原文 + `UE 5.5`** 粘到搜索引擎（Bing / Google）。**把报错里的具体变量名删掉**，只留通用部分，命中率更高。

例：不要搜 `error C2039: 'MechIndex': is not a member of 'ALY_FirePillar'`，改搜 `error C2039 is not a member of UE 5.5 UCLASS`。

#### 9.2.3 第 3 步：问 AI（把上下文给足）

问 AI 时**必须**提供：
1. 完整报错（原文）
2. 相关代码（`.h` 和 `.cpp` 的相关部分）
3. 你刚做了什么改动
4. UE 版本 + 编译方式（VS 还是 Live Coding）

> 💡 **对我（Codex）也一样**：把这个项目文件夹保持在对话里，遇到问题直接把报错贴过来。我能帮你定位到具体行。

#### 9.2.4 第 4 步：最小复现

新建一个**空关卡**或**空类**，只放/只写「出问题的那一个东西」，看它还能不能复现。
- 能复现 → 问题在那个东西本身，好办。
- 不能复现 → 问题在它和别的系统的**交互**上，缩小范围继续试。

#### 9.2.5 第 5 步：二分法

如果是「代码改完后崩了」：
- 注释掉**一半**改动，看是否恢复。
- 恢复 → 问题在被注释的那一半；没恢复 → 在被保留的那一半。
- 重复，直到定位到具体几行。

如果是「关卡里某个区域有问题」：
- 删除一半 Actor，看是否恢复。

#### 9.2.6 第 6 步：回退

```powershell
git status              # 看改了什么
git stash               # 临时收起改动，回到干净状态
git checkout -- .       # 丢弃所有未提交改动（慎用！）
git log --oneline       # 找到最近能跑的 commit
git reset --hard <sha>  # 回到那个 commit（会丢失未提交内容！）
```

> ⚠️ `git reset --hard` 会**永久丢失未提交的改动**。用之前先 `git stash` 或复制一份项目。

#### 9.2.7 第 7 步：绕过

**如果一个小功能卡了 3 天，果断换实现方式。**
例如：
- 角度对齐搞不定 → 改成「用枚举记旋转次数」，每转一次计数 +1，转到第 N 次就接通。
- 风场物理不稳定 → 改成「零重力 + 每帧直接写 `Velocity.Z` 的匀速电梯」（见 `03` 的 3.17）。
- 移动平台玩家站不稳 → 改成「玩家站上去时直接 Attach 到平台」。

> **能跑起来的笨方案 > 跑不起来的优雅方案。**

#### 9.2.8 第 8 步：求助

- **Epic 官方论坛**（英文，回复快）
- **UE 中文社区 / 知乎 UE 专栏**
- **B 站 UE 教程评论区**（很多人踩过同样的坑）
- **Reddit r/unrealengine**
- **Discord：Unreal Slackers**

**求助模板（照抄）：**
```
【环境】UE 5.5 + VS 2022，Windows 11

【报错】<完整报错原文>
```

### 9.3 关于「要不要放弃 C++」的原则

用户你问过「C++ 和蓝图怎么合作」。这里给你一个**止损原则**：

**原则：C++ 是「骨架」，蓝图是「血肉」，但骨架可以少一些。**

| 情况 | 建议 |
| --- | --- |
| 这个系统以后要复用 / 要给别人看 / 逻辑复杂 | **用 C++**（玩家、交互、机关基类、谜题算法） |
| 这个系统是一次性的表现 / 数值调整 / 关卡独有 | **用蓝图**（材质、VFX、UI、音频、演出） |
| 这个系统你实在写不出来，而且卡了 3 天 | **降级为蓝图**，先让项目能跑 |
| 面试要讲「C++ / 蓝图分工」 | 必须至少有 3～5 个 C++ 类，且是**核心玩法类** |

> 🎯 **对你（gameplay 方向）而言，最不能放弃的 C++ 是：玩家角色、交互组件、机关基类、谜题算法、流程总控。** 这五个用 C++，你的作品集就有说服力了。其余的随便。

### 9.4 应急交付路线（如果你 6 周后要投简历）

**如果时间只剩 6 周，按这个顺序做：**

| 周 | 做什么 | 砍掉什么 |
| --- | --- | --- |
| 第 1 周 | M0 + M1（环境和手感） | — |
| 第 2 周 | M2（白盒，尺寸可以粗糙） | 精细对齐 |
| 第 3 周 | M3 + M4（交互 + 火方碑） | — |
| 第 4 周 | M5 + M6（旋转桥 + 两处谜题） | 谜题只做一轮 |
| 第 5 周 | M7 + M8（风场 + 组装） | 检查点简化 |
| 第 6 周 | M9 简化版 + M11（打包） | 大部分美术、音频、演出 |

**应急交付版的最低配置：**
- ✅ 六平台白盒 + 基础材质（不用精细模型）
- ✅ 交互 + 火方碑 + 旋转桥 + 两处谜题（哪怕各只有一轮）
- ✅ 风场电梯 + 全程通关
- ✅ 打包 exe + 3 分钟录像 + README

> 🎯 **一个「玩法完整但画面朴素」的 demo，比「画面精美但只能走两步」的 demo 强 10 倍。** 尤其对 gameplay 岗位。

## 第二部分 · 新手必踩的 50 个坑

### 9.7 编译与项目类（10 个）

| # | 坑 | 症状 | 解决 |
| --- | --- | --- | --- |
| 1 | 创建项目时选了蓝图模板 | 没有 C++ 代码，后面加不上 | 重建，选 **C++** 模板；或手动 Add C++ Class |
| 2 | 项目建在 C 盘 | C 盘爆满，系统卡死 | 项目必须放 E 盘 |
| 3 | 没装 VS「使用 C++ 的游戏开发」工作负载 | 编译找不到编译器 | VS Installer → 修改 → 勾选该工作负载 |
| 4 | MSVC 版本过新/过旧 | toolchain 错误 | 换 14.36/14.38；或退回 UE 5.3 |
| 5 | 编辑器开着改 `.h` | Live Coding 报错或崩溃 | **改头文件必须关编辑器重新编译** |
| 6 | 项目路径/用户名含中文 | 编译/打包莫名报错 | 路径全英文（你的 `E:\UE_projects` 没问题） |
| 7 | 手动改 C++ 类名/文件名 | 一堆重定向错误 | 用 IDE 的重命名功能 |
| 8 | 删了 C++ 类 | 引用的蓝图全崩 | 删除前先搜索引用（右键 → Reference Viewer） |
| 9 | 忘了加 `UPROPERTY` | UObject 指针被 GC，随机崩溃 | 所有 UObject 指针成员必须加 |
| 10 | 忘了 `GENERATED_BODY()` | 编译宏错误 | 类定义第一行必须有； `.generated.h` 放 include 最后 |

### 9.8 蓝图与 C++ 协作（10 个）

| # | 坑 | 症状 | 解决 |
| --- | --- | --- | --- |
| 11 | 蓝图里重复实现 C++ 逻辑 | 行为诡异、双重触发 | 逻辑只写一处（见 `04_蓝图与C++协作.md` 分层） |
| 12 | C++ 里直接引用 BP 资产 | 编译不过/循环依赖 | C++ 只引用基类，资产在蓝图里设 |
| 13 | 蓝图重新指定父类 | 资产数据丢失 | 早期定好继承链，别中途换父类 |
| 14 | 改 `UPROPERTY` 名字 | 蓝图里数值清零 | 改名时选保留重定向（Core Redirect） |
| 15 | `BlueprintNativeEvent` 忘了 `_Implementation` | 链接错误 | 声明必须是 `Func_Implementation` |
| 16 | 在构造函数里访问 World | 编辑器崩溃 | 世界操作放 `BeginPlay` |
| 17 | `Tick` 里做昂贵操作 | 帧率暴跌 | 用 Timer / 事件 / 重叠替代 |
| 18 | `Cast` 失败没判空 | 崩溃 | Cast 后必须判 `IsValid` |
| 19 | 接口只在 C++ 实现，蓝图没法调 | 蓝图里找不到接口函数 | 接口函数加 `BlueprintCallable` / `BlueprintImplementableEvent` |
| 20 | 蓝图中断点不触发 | 逻辑没进到那里 | 用 Print String 排查；确认事件真的被调用 |

### 9.10 玩法与物理（13 个）

| # | 坑 | 症状 | 解决 |
| --- | --- | --- | --- |
| 31 | **角度用浮点数 `==` 比较** | 旋转机关永远接不通 | 用 `FMath::Abs(FMath::FindDeltaAngleDegrees(A,B)) < 5.0f` |
| 32 | **环形数组左右索引越界** | 联动谜题崩溃/行为错乱 | 用取模： `(i-1+N)%N`、 `(i+1)%N` |
| 33 | **风场用 `AddForce` 或加速度累加** | 玩家越飞越快、飞出地图 | 进柱后**每帧直接写 `Velocity.Z = RiseSpeed`**（匀速） |
| 34 | 柱内按 W 几乎不往前走 | 没调 `AirControl`（默认约 0.05） | 进柱时设 `AirControl = 1.0`（**控制是调大不是减弱**） |
| 35 | 柱顶高度抖动 | 临界高度一帧升一帧停 | 加 30 uu 迟滞（`CeilingTolerance`） |
| 36 | E 边缘「踩上去就飘」 | 风场体积与 E 的可行走面重叠 | 改成接壤不重叠，间隙 0～100 uu |
| 37 | 出柱后一直飘着不回地面 | 没还原 `GravityScale` / `AirControl` | 出柱时还原三个 CMC 参数 |
| 38 | 风场里玩家时升时不升 | 在风场 Actor 的 Tick 里改角色速度，Tick 顺序不确定 | **施力写在角色自己身上** |
| 39 | 光路碰撞没跟着状态切换 | 玩家能走没接通的桥 / 接通的桥走不了 | 状态变化时同步 `SetCollisionEnabled` |
| 40 | 旋转过程中重复触发交互 | 角度错乱 | 旋转中 `bIsRotating = true`，禁止再次交互 |
| 41 | 掉出地图没处理 | 玩家无限下坠 | Kill Z + 检查点重生 |
| 42 | 重生后速度没清零 | 继续掉 | `SetActorTransform` 后 `SetPhysicsLinearVelocity(0)` |
| 43 | 交互射线打到自己 | 提示不显示 | `AddIgnoredActor(this)`；检查碰撞通道 |

## 🐛 常见坑

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 看到报错不看 Log，直接改代码 | 越改越乱 | 先复制完整报错原文 |
| 在同一个 bug 上死磕一周 | 项目停滞 | 3 天原则：换方案、简化或绕过 |
| 把 Warning 当 Error 改 | 浪费大量时间 | 只处理红色 Error，预警後看 |
| 不留复现步骤 | 下次还会重踩 | 把解决过程记进 DevLog |
