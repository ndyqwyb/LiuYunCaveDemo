### 3.2 机关一 · 火元素方碑 `ALY_FirePillar`

**职责**：一个可以被点燃/熄灭的方碑，是谜题的基本单元。

| 项 | 规格 |
|---|---|
| 父类 | `ALY_MechanicBase` |
| 交互方式（**已定 A1**） | 走近 → 准星对准 → 提示「E 点燃」→ 按 `IA_Interact` |
| 组件 | `UStaticMeshComponent`（石柱外体，**中部镂空**）、 `UStaticMeshComponent`（内部火核）、 `UNiagaraComponent`（顶部火焰）、 `UPointLightComponent`、 `ULY_InteractComponent`、 `USceneComponent`（封印罩挂点） |
| 尺寸（**已定 · 真人尺度**） | 底座 150×150×30；柱身 110×110×120（中段镂空 60×60×50）；火核 Ø70×80；顶部火焰 ≈70×100；**总高 ≈220**；封印罩圆柱 Ø260×300 |
| 关键属性 | `int32 MechIndex`（谜题编号）、 `bool bIsLit`、 `bool bIsSealed`、 `FLinearColor LitColor / UnlitColor` |
| 方法 | `SetLit(bool bNewLit)`、 `IsLit()`、 `ToggleLit()`、 `SetSealed(bool bNewSealed)` |
| 事件 | `OnLitChanged(bool bIsLit)`、 `OnSealedChanged(bool bIsSealed)` |
| 视觉（**已定 B2**：镂空石柱 + 内部火核） | **暗态**：火核隐藏、石柱暗石材质、无光；**亮态**：火核显现并自发光（暖金/红橙）+ 顶部火焰粒子 + 点光；过渡 `0.25s`。火核是**柱身中段镂空处一颗悬浮的发光晶体**，不是整根柱子发光 |
| 封印（见 `3.26`） | `bIsSealed == true` 时整体套透明能量罩，罩子存在期间 `CanInteract()` 返回 false |
| 蓝图负责 | 切暗/亮材质实例、显隐火核、播/停火焰粒子、开关点光源、播点火/熄灭音效 |
| 参数 | `LitIntensity = 1500`、 `UnlitIntensity = 150`、 `TransitionTime = 0.25s`、`FlameScale ≈ 0.7` |
| 易错点 | ① 灯光别开太多（同场多个方碑同时开动态光会掉帧）→ 关闭阴影或改用 Emissive 假光 ② 火核与镂空对不齐会穿模 → 只在蓝图里调火核的 `RelativeScale`/`RelativeLocation`，**不要改模型** ③ 粒子在相机里穿帮 → 调 `Niagara` 的 `Bounds` |

### 3.3 机关二 · 旋转光桥 `ALY_RotatingBridge`

**职责**：本 Demo 的招牌机关。旋转方向，让光路对接。

| 项 | 规格 |
|---|---|
| 父类 | `ALY_MechanicBase` |
| 交互方式（**已定 A2**：左右两个按钮） | 转盘中心有**两个独立交互点**：**左键 = −90°**、**右键 = +90°**；按一次转一个 `RotationStep`。**两个方向都能用**，玩家转反了可以立刻转回来，不存在「只能单向加」 |
| 组件 | `USceneComponent`（旋转轴心）、 `SM_LY_BridgeHub`（圆形转盘基座）、 `SM_LY_BridgeStub` **×2**（石路残段，铺在平台面上）、 `SM_LY_BridgeButton` **×2**（左右按钮）、 `UStaticMeshComponent`（光路段，用 Cube 缩放，**不建模**）、 `ULY_InteractComponent` **×2**、碰撞盒 |
| 关键属性 | `float RotationStep`（`90` 或 `180`）、 `float RotationDuration = 0.8f`、 `float CurrentYaw / TargetYaw`、 `bool bIsRotating`、 `bool bIsAligned`、 `TArray<ALY_LightPath*> LinkedPaths` |
| 方法 | `RotateStep(int32 Direction)`、 `SnapTo(int32 StepIndex)`、 `IsAligned()` |
| 事件 | `OnRotationStarted`、 `OnRotationFinished(float NewYaw)`、 `OnAligned()`、 `OnUnaligned()` |
| 石路残段（**已定**） | **一个平台面上只铺一段可见石路**，尺寸 **长 700 × 宽 350 × 厚 20**；700 < 半径 800（Ø1600），**任何角度都不超出平台边界、不会悬空穿模**。远端留断口，只覆盖缺口的 30～40%，其余由激活后的光桥补完。视觉读法：「这里断了 → 转对方向 → 金光把路接上」 |
| 两种预置（**已定**，只做 1 个转盘 + 1 段石路模型） | `BP_LY_RotatingBridge_Straight180`（残路夹角 **180°**）→ 用于 ③号盘（2↔4 / 10↔11）与 ⑨号盘（8↔10）；`BP_LY_RotatingBridge_Corner90`（残路夹角 **90°**）→ 用于 ⑤号盘（4↔6 / 4↔7）。**同一套 C++ + 同一个石路模型，只改蓝图里残路的相对旋转** |
| 尺寸约定（**重要**） | 石路 **宽 350uu × 长 700uu**（长按平台半径预留余量），**光桥宽度去匹配石路**（不是反过来）。绝不对网格做「裁剪」，改长度只在建模阶段定，或仅沿长度轴缩放 |
| 蓝图负责 | 转盘/石路/按钮材质、旋转音效、每转 90° 的机械**卡位感**、对齐瞬间的光效与音效 |
| 实现要点 | `RotationPivot` 做相对旋转； `Tick` 里 `FMath::FInterpConstantTo` 匀速插值；对齐判定用 `FMath::Abs(FMath::FindDeltaAngleDegrees(A,B)) < Tolerance`（容差 5°） |
| 玩家位置（**防穿帮**） | 按钮放在**转盘中心**：圆盘旋转对称，玩家站中心转 90° 不会被甩下去。若玩家站到伸出的石路上再转 → UE 不会带着角色转，人会滑落 |
| 易错点 | ① 用 `==` 比较角度永远不会真 ② 旋转中重复交互导致角度错乱 → `bIsRotating` 时 `CanInteract` 返回 false ③ 光路对齐判定必须在旋转**结束后**再算，不要在过程中每帧算 ④ 石路与光桥宽度对不上 → 先定石路、光桥去适配 ⑤ 石路超出平台边界 → 残段长度按平台半径预留余量 |

### 3.4 机关三 · 记忆顺序谜题

**职责**：管理「播放序列 → 玩家复现 → 判定」的完整状态机。

| 项 | 规格 |
|---|---|
| 类 | `ALY_SequencePuzzleManager`（Actor）+ `ALY_PuzzleSwitch`（启动开关 / 石碑）+ `ULY_TimeSequencePuzzleComponent`（可选组件化） |
| 状态机（**已更新**） | `Sealed → Countdown → ShowingSequence → WaitingInput → Evaluating → RoundComplete → AllComplete`（用 `enum class ELY_PuzzleState`） |
| 封印（**已定**） | **每根方碑一个透明能量罩**（复用 `ALY_Seal`，见 `3.26`），未进行的轮次全部处于封印态 |
| 启动方式（**已定**） | **每轮都要交互一次开关** `ALY_PuzzleSwitch` → 该轮开罩 + 开始倒计时 + 播放顺序；显示完才允许玩家交互 |
| 倒计时（**已定**） | **每轮独立倒计时，且逐轮递增**；倒计时**从开罩就开始**（包含播放顺序的时间） |
| 超时处理（**已定**） | 倒计时归零 → **重新封印**（退回 `Sealed`），但**已完成的轮次保留**；玩家再次交互开关即可重开当前轮 |
| 进度保存（**已定**） | 已完成轮次写入 `int32 CompletedRounds`，超时/失败**都不清空**，只有点错才重置**当前轮** |
| 关键属性 | `TArray<ALY_FirePillar*> Pillars`、 `TArray<int32> CurrentSequence`、 `TArray<int32> PlayerInput`、 `int32 CurrentRound`、 `int32 CompletedRounds`、 `int32 MaxRounds = 3`、 `float RoundTimeLimit` |
| 方法 | `StartPuzzle()`、 `StartRound()`、 `GenerateSequence(int32 Length)`、 `PlaySequence()`、 `OnPillarInteracted(int32 Index)`、 `EvaluateInput()`、 `ResetRound()`、 `OnCountdownExpired()`、 `GetRemainingTime()` |
| 事件 | `OnSequenceStarted`、 `OnPillarFlashing(int32 Index)`、 `OnRoundComplete(int32 Round)`、 `OnPuzzleFailed`、 `OnPuzzleCompleted`、 `OnCountdownTick(float Remaining)`、 `OnRoundSealed()` |
| 蓝图负责 | 每题播放时给对应方碑加特殊材质/音效；**倒计时 UI**（数字 + 进度条，剩余 10 秒变红 + 心跳音）；轮次切换的 UI 提示；失败时的震动反馈 |
| 数据 | `ULY_PuzzleConfigDataAsset`： `TArray<int32> RoundLengths = {3,4,5}`、 `TArray<float> RoundTimeLimits = {40, 55, 70}`（秒，**逐轮递增**）、 `FlashDuration`、 `GapDuration`、 `bAllowRandom` |
| 易错点 | ① 播放序列时玩家能交互 → 必须锁输入 ② 用 `Timer` 播放序列而不是 `Tick` 累加 ③ 点错**只重置当前轮**（别清空全部进度）④ **超时后别把 `CompletedRounds` 归零**，否则玩家会暴怒 ⑤ 倒计时用 `SetTimer` + `GetRemainingTime()` 查询，**不要每帧 `Tick` 累减 float**（会漂移）⑥ 不要硬编码原版序列 |

### 3.5 机关四 · 联动翻转谜题 `ULY_ToggleRingPuzzleComponent`

**职责**：6 个火柱围成环，交互翻转自己 + 左右邻居。

| 项 | 规格 |
|---|---|
| 类型 | `UActorComponent`（挂在一个管理 Actor 上，或者做 `ALY_ToggleRingPuzzleManager`） |
| 关键属性 | `TArray<ALY_FirePillar*> RingPillars`（数量 = 6）、 `int32 RingSize`、 `bool bAllowReset` |
| 方法 | `ToggleIndex(int32 Index)`（内部： `Toggle(Index-1)`, `Toggle(Index)`, `Toggle(Index+1)`）、 `IsSolved()`、 `ResetAll()` |
| 事件 | `OnPillarToggled(int32 Index)`、 `OnSolved()` |
| 算法要点 | 环形索引必须取模： `((i % N) + N) % N` |
| 可解性验证 | 提供 `bool ValidateSolvable(const TArray<bool>& Initial)`：用 BFS 在 2^6 = 64 个状态里搜解 |
| 蓝图负责 | 每个火柱的视觉反馈；全解时的全场特效 |
| 易错点 | ① 环形索引写错 ② 没有「重置」导致玩家卡死 ③ 6 个火柱没有明确编号/位置顺序，玩家看不懂「相邻」 |

### 3.6 机关五 · 风场 `ALY_WindField`

**运行原则（已定 · 零重力匀速电梯）**：风场不是「吹」，是**双向电梯**。进柱 → 零重力匀速升到柱顶 → 悬停 → 自己朝目标平台方向移出 → 出柱恢复重力落下去。

| 项 | 规格 |
|---|---|
| 父类 | `AActor`（或 `ALY_MechanicBase`，因为它也要能被「开启」） |
| 组件 | `UBoxComponent` 或 `UCapsuleComponent`（作用体积，**只 Overlap 不 Block**）、 `UNiagaraComponent`（气流粒子）、 `UStaticMeshComponent`（地面圆环）、 `UAudioComponent`（风声） |
| 尺寸（**已定**） | 圆柱 **Ø800（R400）**；底面 = ⑦号岛顶面 **+600**；柱顶 = **+1650**（⑧号岛顶面 +1200 再高 450）；`ColumnHeight = 1050` |
| 运行方式（**已定 · 方案甲「零重力匀速电梯」**） | 进柱 → `GravityScale = 0`、`AirControl = 1.0`、**每帧直接写 `Velocity.Z`（匀速上升，不是给力）**；到柱顶 → `Velocity.Z = 0`，零重力下只能动 XY；出柱 → 还原参数，正常重力接管 |
| 关键属性 | `float RiseSpeed = 600`（uu/s，匀速）、`float ColumnHeight = 1050`、`float FieldRadius = 400`、`float CeilingTolerance = 30`（柱顶迟滞） |
| 保险开关 | `bool bTopPushEnabled = false`、`float TopPushSpeed = 500` —— **默认关闭**，实测落点不够再打开 |
| **双向通行（已定）** | 风场没有单向阀门：⑦→⑧ 是「被抬到柱顶再往北移出」，⑧→⑦ 是「走进柱体 → 被抬到柱顶 → 往南移出 → 自由落体」。**玩家乘风场回来是合法路线**，所以不存在死锁 |
| 方法 | `SetFieldActive(bool)`、 `GetCeilingWorldZ()` |
| 开启条件（**已定**） | **累计打开 4 个宝箱**（1·2·3·4）后，由 `ALY_GameFlowManager` 调用 `SetFieldActive(true)`。宝箱 4 在 ⑦号岛，**到达即可开**；⑥号岛三轮谜题完成只解锁宝箱 1·2·3 |
| 事件 | `OnWindStateChanged(bool bActive)` |
| 蓝图负责（**已定 B1**） | 地面**发光圆环** `SM_LY_WindRing`（未激活暗、激活亮）+ 上升气流 Niagara + 风声音效 |
| 几何关系（**已定**） | 风场与 ⑦、⑧ 两座岛**接壤、不重合**（两侧各留 0～100 uu）；**柱顶高于 ⑧ 地面 450 uu**；⑧号岛靠风场一侧**不放栏杆**，可选加 250 uu 宽「接驳唇」小凸台 |
| 易错点 | ① 用 `AddForce`/加速度累积 → 越飞越快、飞出地图 ② 忘了把 `AirControl` 调到 1.0 → 柱内按 W 几乎不动 ③ 体积和 ⑦/⑧ 的**可行走面重叠** → 边缘变成「踩上去就飘」的怪区域 ④ 出柱不还原 `GravityScale` → 玩家永远飘在空中 ⑤ ⑧号岛近侧放栏杆 → 玩家撞栏掉下去 |

### 3.7 机关六 · 宝箱 `ALY_TreasureChest`

| 项 | 规格 |
|---|---|
| 父类 | `ALY_MechanicBase` |
| 交互方式（**已定 A1**） | 走近 → 提示「E 开启」；未解锁时提示「此箱尚未解锁」 |
| 关键属性 | `ELY_ChestQuality Quality`（Common / Exquisite / Precious）、 `bool bIsUnlocked`、 `bool bIsOpened` |
| 方法 | `Unlock()`、 `Open()`、实现 `ILyInteractable::Interact` |
| 组件 | `UStaticMeshComponent`（箱体）、 `UStaticMeshComponent`（盖子，会转）、 `ULY_InteractComponent`、 `USceneComponent`（封印罩挂点） |
| 视觉（**已定 B1**） | 标准宝箱（箱体 + 可转盖子）；未解锁时换 `MI_LY_Chest_Locked` 暗材质 |
| 封印表现（**已定**） | 未解锁时套一个**略大于箱体的透明能量罩**（复用 `ALY_Seal`，见 `3.26`）：发光 + 缓慢脉动 + 正面一个小锁符号（Decal） |
| 解锁演出（**已定**） | ① 封印罩**缓慢消散**（溶解材质 1.2～1.8s，别用缩放消失）② 播放解锁音效 ③ 箱体材质切亮 ④ 地面发光圆环闪 2 下（复用风场圆环）。全程 **0.8～1.2s**，不打断玩家移动 |
| 屏幕指引（**已定**） | 每解锁一个宝箱 → HUD 显示「宝箱符号 + 指向箭头」；**同时有多个待开宝箱时，只指引最近的一个**，开掉后自动指向下一个 |
| 关卡分布（**已定 · 共 5 个**） | 宝箱 1·2·3 在 ⑥号岛（三轮谜题各解锁 1 个，**未解锁时套封印罩**）；宝箱 4 在 ⑦号岛（**无前置，到达即可开**）；宝箱 5 在 ⑩号岛（环形谜题全亮后解锁） |
| 不做 | ❌ 不做逐箱镜头演出（5 个箱子各拉一次镜头会打断节奏）。**只允许在「宝箱解锁 → 罩子消散」时给一次很轻的镜头偏转（≤0.3s、不超过 5°）**，见 `3.21` |
| 蓝图负责 | 盖子开合动画（Timeline 转 `FRotator`）、开箱特效、开箱音效、品质差异材质 |

### 3.12 交互系统 `ILY_Interactable` + `ULY_InteractComponent`

**这是整个 Demo 使用频率最高的系统。** 玩家不关心对面是方碑、宝箱还是石柱。

| 分工 | 内容 |
|---|---|
| **C++（接口）** | `CanInteract()` / `Interact()` / `GetInteractPrompt()` 三个虚函数 |
| **C++（玩家）** | 每 0.1 秒（用 Timer，不要每帧）从相机做射线检测，找可交互物，更新 `CurrentInteractTarget` |
| **C++（玩家）** | 按下 `IA_Interact` → 调用目标的 `Interact(this)` |
| **蓝图（玩家）** | 把 `InteractPrompt` 的文字显示到 `WBP_LY_InteractPrompt` |
| **蓝图（Widget）** | 提示框的样式、位置、淡入淡出动画 |
| **验收** | 走到任意机关前都能看到提示；离开就消失；按 E 一定生效 |

```cpp
// 玩家侧：寻找可交互目标
void ALY_PlayerCharacter::UpdateInteractTarget()
{
    FHitResult Hit;
    const FVector Start = CameraComp->GetComponentLocation();
    const FVector End   = Start + CameraComp->GetForwardVector() * InteractRange;

    FCollisionQueryParams Params;
    Params.AddIgnoredActor(this);          // ★ 别打到自己

    if (GetWorld()->LineTraceSingleByChannel(Hit, Start, End, ECC_Visibility, Params))
    {
        AActor* HitActor = Hit.GetActor();
        if (HitActor && HitActor->Implements<ULY_Interactable>())
        {
            if (CurrentInteractTarget.Get() != HitActor)
            {
                CurrentInteractTarget = HitActor;
                OnInteractTargetChanged.Broadcast(HitActor);   // 蓝图更新 UI
            }
            return;
        }
    }
    // 没打到任何东西 → 清空目标
    CurrentInteractTarget = nullptr;
    OnInteractTargetChanged.Broadcast(nullptr);
}
```

**关键参数**： `InteractRange = 250～350`（太小够不到，太大能隔墙交互）。
**坑**：
- 射线打到了自己的胶囊体 → `AddIgnoredActor(this)`
- 机关碰撞体没勾 `Visibility` 通道 → 射线穿过机关打到墙上
- 提示文字在蓝图中硬编码 → 应该由 `GetInteractPrompt()` 返回，不同机关不同文字

### 3.14 旋转光桥 `ALY_RotatingBridge`

| 分工 | 内容 |
|---|---|
| **C++** | 旋转角度插值、对齐判定、 `bIsRotating` 锁、 `RotateStep()`、 `OnAligned` 事件 |

**C++ 核心逻辑（时序）：**
```cpp
void ALY_RotatingBridge::RotateStep(int32 Direction)
{
    if (bIsRotating) return;                    // ★ 关键：锁住
    TargetYaw += RotationStep * Direction;
    bIsRotating = true;
    OnRotationStartedVisuals();                 // 蓝图：播音效、启动光效
}

void ALY_RotatingBridge::UpdateRotation(float DeltaSeconds)
{
    if (!bIsRotating) return;

    const float Current = RotationPivot->GetRelativeRotation().Yaw;
    const float NewYaw = FMath::FInterpConstantTo(Current, TargetYaw, DeltaSeconds,
                                                  RotationStep / RotationDuration);
    RotationPivot->SetRelativeRotation(FRotator(0.f, NewYaw, 0.f));

    if (FMath::Abs(FMath::FindDeltaAngleDegrees(NewYaw, TargetYaw)) < 0.1f)
    {
        RotationPivot->SetRelativeRotation(FRotator(0.f, TargetYaw, 0.f));
        bIsRotating = false;
        CheckAlignment();                       // ★ 转完再判定
    }
}
```

**坑**：
- 用 `==` 比较角度**永远不会成立** → 必须用 `FindDeltaAngleDegrees` + 容差
- 旋转中每帧判定对齐 → 会在中途误触发
- 玩家站在桥上时旋转 → 会被甩出去 → 加 `bIsRotating` 时禁止交互（简单方案）或锁定玩家位置（复杂方案）

### 3.15 记忆顺序谜题 `ALY_SequencePuzzleManager`

**这是本 Demo 最复杂的系统，也是最能体现你能力的部分。**

| 分工 | 内容 |
|---|---|
| **C++（状态机）** | 状态机、序列随机生成、输入记录与判定、轮次管理、失败/成功事件 |
| **C++（倒计时）** | `RoundTimeRemaining` + `FTimerHandle`（1 秒或 0.1 秒 tick）→ 广播 `OnCountdownTick`；超时调 `OnCountdownExpired()` |
| **C++（进度）** | `CompletedRounds` 永久保留；点错只 `ResetRound()` 当前轮；超时只退回 `Sealed`，**不动已完成轮次** |
| **C++（封印）** | 每根方碑各有一个 `BP_LY_Seal`；`Sealed` 态全开、`Countdown/ShowingSequence/WaitingInput` 态全关 |
| **蓝图** | 每题播放时的方碑高亮特效、轮次切换的 UI 提示、失败时的屏幕震动 |
| **蓝图（Widget）** | 显示「第 1/3 轮」「记住顺序」「按顺序点燃」+ **倒计时数字与进度条**（剩 10 秒变红 + 心跳音） |
| **DataAsset** | `DA_LY_PuzzleConfig`：轮次长度、**每轮时限（递增）**、闪烁时长、间隔、是否随机 |
| **关卡** | 谜题区放 1 个 `BP_LY_PuzzleSwitch`（启动开关/石碑），每轮交互一次 |
| **验收** | 每轮都要交互开关才开罩；倒计时可见且逐轮变长（40/55/70s）；超时后重新封印但**已完成轮次不丢**；三轮完成后**宝箱 1·2·3 全部解锁**（风场不在这一刻开启，须累计开满 4 个宝箱，见 3.6） |

**状态机（`ELY_PuzzleState`）：**
```
Sealed ──交互 PuzzleSwitch──► Countdown ──(同时开始播放)──► ShowingSequence
   ▲                                                              │
   │                                                          播放完
   │                                                              ▼
   │                                                        WaitingInput
   │                                                              │
   │                                                         玩家点击
   │                                                              ▼
   │                                                        Evaluating
   │                                                       ╱          ╲
   │                                                    失败            成功
   │                                                       │              │
   │                              ResetRound()（只重置当前轮）         RoundComplete
   │                                                                      │
   │  倒计时归零 → OnCountdownExpired()（重新封印，保留已完成轮次）        │ 三轮完成
   └──────────────────────────────────────────────────────────────────────▼
                                                                    AllComplete
                                          （累计打开 4 个宝箱后，风场才开启）
```

**用 Timer 播放序列（不要用 Tick 累加）：**
```cpp
void ALY_SequencePuzzleManager::PlaySequence()
{
    SetState(ELY_PuzzleState::ShowingSequence);
    for (int32 i = 0; i < CurrentSequence.Num(); ++i)
    {
        const int32 PillarIndex = CurrentSequence[i];
        const float Delay = i * (FlashDuration + GapDuration);
        FTimerHandle Handle;
        GetWorldTimerManager().SetTimer(Handle, FTimerDelegate::CreateWeakLambda(this,
            [this, PillarIndex]()
            {
                if (Pillars.IsValidIndex(PillarIndex))
                {
                    Pillars[PillarIndex]->FlashOpen(FlashDuration);
                    OnPillarFlashing.Broadcast(PillarIndex);   // 蓝图：音效 + 特效
                }
            }), Delay, false);
    }
    // 全部播完后进入 WaitingInput
    FTimerHandle DoneHandle;
    GetWorldTimerManager().SetTimer(DoneHandle, this,
        &ALY_SequencePuzzleManager::EnterWaitingInput,
        CurrentSequence.Num() * (FlashDuration + GapDuration) + 0.3f, false);
}
```

**坑**：
- **播放序列时玩家能交互** → 必须锁输入（`ELY_PuzzleState::ShowingSequence` 时 `CanInteract` 返回 false）
- **硬编码原版序列**（1-5-4 / 3-5-1-4 / 2-4-1-5-3）→ 应该实现「规则 + 随机」，更准确也更显功力
- **点错直接清空所有进度** → 太挫败，只重置当前轮
- **三轮之间没有停顿** → 玩家分不清轮次

void ULY_ToggleRingPuzzleComponent::ToggleIndex(int32 Index)

}

### 3.17 风场 `ALY_WindField`

**运行原则（已定 · 零重力匀速电梯）**：风场不是「吹」，是**双向电梯**。进柱 → 零重力匀速升到柱顶 → 悬停 → 自己朝目标平台移出 → 出柱恢复重力落下去。**全程玩家有横向控制权，全程不可能失败。**

| 分工 | 内容 |
|---|---|
| **C++（风场）** | `UBoxComponent` 重叠检测、参数、开/关状态、`EnterWindField(this)` / `ExitWindField()` 通知 |
| **C++（角色）** | ★ **施力放在 `ALY_PlayerCharacter` 里**：改 CMC 参数 + 每帧写 `Velocity.Z`（代码见 `04` 的 4.21） |
| **蓝图（风场）** | 气流 Niagara、风声音效、地面圆环暗/亮切换、柱体材质流动 |
| **蓝图（角色）** | 脚底风环粒子开关；动画蓝图读 `bIsInWindField` |
| **开启来源** | `ALY_GameFlowManager` 在 `ChestsOpened == 4` 时调用 `SetFieldActive(true)`；**不由谜题 Manager 直接触发** |
| **关卡** | ⑦号岛摆 1 个（底面 +600）；与 ⑦、⑧ 两岛接壤不重合；柱顶 = **+1650** = ⑧号岛地面 +450 uu；⑧号岛近侧不放栏杆 |
| **验收** | ⑦→⑧：进柱一定能升到顶、按 W 一定能落到 ⑧ 上；**⑧→⑦ 也一定能回得来**；全程不可能失败 |

**三阶段逻辑（就这三句）：**
```
① 上升段  角色Z < 柱顶-30  →  Velocity.Z = RiseSpeed   （每帧直接写，匀速）
② 悬停段  角色Z ≥ 柱顶-30  →  Velocity.Z = 0            （零重力，只能动 XY）
③ 出柱      EndOverlap     →  还原 GravityScale / AirControl → 正常重力接管
```

**进柱时改的 CMC 参数（出柱逐个还原）：**

| 参数 | 平常 | 风场内 | 为什么 |
|---|---|---|---|
| `GravityScale` | 1.0 | **0** | 零重力 |
| `AirControl` | 0.05～0.35 | **1.0** | ★ **不调这个，柱内按 W 几乎不往前走，「手动飞到平台上」根本不成立** |
| `BrakingDecelerationFalling` | 0 | **1200** | 松手能停住，不会一直飘 |
| `FallingLateralFriction` | 0 | 0 | 保持 0，不要加阻力 |

> 🔑 **注意「控制系数」的方向是反的**：空中控制不是要**减弱**，而是要**调到最大**。UE 的 `AirControl` 默认约 0.05，意思是腾空后几乎不能转向。

**为什么「接壤 + 柱顶更高」就够了（几何验算）：**

玩家在**悬停状态**出柱时，**竖直速度为 0**（不是下坠中），所以是从柱顶开始自由落体：

| 柱顶比 ⑧号岛地面高 | 下落时间 | 横向 400 uu/s 落点 | 横向 300 uu/s 落点 |
|---|---|---|---|
| 300 uu | 0.78 s | E 边缘内 313 uu | 235 uu |
| **450 uu（已定）** | 0.96 s | E 边缘内 **383 uu** | 287 uu |
| 600 uu | 1.11 s | E 边缘内 444 uu | 333 uu |

⑧号岛直径 2000 uu（R1000），落点余量充足。**所以不需要横向助推。** 另外还有两笔白送的余量：① Overlap 按**胶囊体**判定，`EndOverlap` 触发时胶囊中心已越过边界约一个胶囊半径（34～42 uu）；② 可选的 250 uu「接驳唇」（比 ⑧ 地面低 200 uu、金色光边的小凸台）。

> 🔁 **反向（⑧→⑦）同理**：⑧号岛（+1200）往南走进柱体 → 被抬到柱顶 +1650 → 往南移出 → 自由落体 450 uu 落到 ⑦号岛（+600）。⑦号岛直径 1800 uu（R900），同样够落。

**动画状态机（`ABP_LY_Player`）：**

```
Idle/Run ──腾空──► Fall ──bIsInWindField──► WindRise ──到达柱顶──► WindHover ──出柱──► Fall ──落地──► Land
```

| 项 | 做法 |
|---|---|
| 触发条件 | C++ 里的 `bIsInWindField`（`BlueprintReadOnly` 布尔），**进出各设一次，不要每帧轮询比对** |
| `WindRise` 姿势 | **复用 `Fall`**，零新动画成本；想加分再去 Mixamo 拿一条免费 `Floating` / `Hover` 混进去 |
| `WindHover` 姿势 | 同上；可加 1D Blend 用 `Velocity.Z` 做细微变化 |
| 柱内跳跃 | **屏蔽跳跃输入**（否则玩家困惑「为什么跳不动」）；可选把空格改成「脱离气流出柱下降」 |
| 附加表现 | 脚底风环粒子 + 相机 FOV +3～5 |

**坑**：
- 用 `AddForce` 或加速度累加 → 速度一直涨、飞出地图 → **每帧直接写 `Velocity.Z`**
- 忘了把 `AirControl` 调到 1.0 → 玩家在柱内按 W 没反应
- 体积和 E 的**可行走面重叠** → E 边缘变成「踩上去就飘」的怪区域（**接壤可以，重叠不行**）
- 在**风场 Actor** 的 Tick 里改角色速度 → 两个 Actor 的 Tick 顺序不确定，时灵时不灵 → **施力放在角色自己身上**
- 出柱不还原 `GravityScale` / `AirControl` → 玩家永远飘着
- 柱顶没有迟滞 → 在临界高度一帧升一帧停，抖得难看 → 用 30 uu 迟滞
- ⑧号岛近侧放了栏杆 → 玩家撞栏掉下去
- 把风场做成单向阀门 → 玩家不敢往上走（**本 Demo 明确不做单向**，双向可回）

**逐段点亮（用 Timer，不要用复杂 Timeline）：**
```cpp
void ALY_LightPath::ActivatePath()
{
    bIsActive = true;
    SetCollisionEnabled(true);              // ★ 同步开碰撞

    for (int32 i = 0; i < Segments.Num(); ++i)
    {
        FTimerHandle Handle;
        GetWorldTimerManager().SetTimer(Handle, FTimerDelegate::CreateWeakLambda(this,
            [this, i]()
            {
                if (Segments.IsValidIndex(i))
                {
                    OnSegmentLit.Broadcast(i);   // 蓝图：让第 i 段材质变亮
                }
            }), i * SegmentDelay, false);
    }
}
```

- 忘记同步开关碰撞 → 玩家走在「看不见的桥」上，或掉下「看起来能走」的桥
- 用 Timeline 做 20 段 → 节点爆炸；用循环 + Timer

### 3.24 碰撞与通道（Collision Channel）

**这是新手最容易踩坑的地方之一。** 建议自定义一个碰撞通道：

| 通道 | 用途 |
|---|---|
| `LY_Interactable` | 交互物（只能被交互射线检测） |
| `LY_LightPath` | 光路（决定玩家能否站在上面） |
| `LY_WindField` | 风场体积（只触发 Overlap，不阻挡） |

**设置位置**：Project Settings → Collision → Trace Channels / Object Channels。

**原则**：
- 能走的物体 → `Block` 玩家的 `Pawn` 通道
- 交互物 → 响应 `LY_Interactable` 通道（让交互射线能打到它）
- 触发器 → 只勾 `Overlap`，不勾 `Block`
- **`KillVolume`** → 只勾 `Overlap`，检测到玩家就送回检查点

| 分工 | 内容 |
|---|---|
| **C++** | `ALY_Checkpoint`：记录位置/旋转； `ULY_CheckpointSubsystem`：保存与恢复 |
| **蓝图** | 检查点的视觉特效（可选） |

### 3.26 跨机关复用件 · 封印罩 `ALY_Seal`（新增）

**这是本项目「复用」意识的最强体现：一个表现件，同时被宝箱和火方碑两个系统使用。**（面试可以专门讲这个）

| 项 | 规格 |
|---|---|
| 职责 | 只负责「罩住一个目标」的**视觉表现**，不含任何谜题逻辑 |
| 父类 | `AActor`（或做成 `USceneComponent`，能直接挂在宿主上更省） |
| 组件 | `UStaticMeshComponent`（`SM_LY_Seal`，**UE 自带 Sphere/Cylinder 缩放即可，不用建模**）+ 脉动发光材质 + `UNiagaraComponent`（消散时播放） |
| 关键属性 | `bool bIsActive`、 `FLinearColor SealColor`、 `float PulseSpeed = 2.0`、 `float DissolveDuration = 1.5` |
| 方法 | `ActivateSeal()`、 `ReleaseSeal(bool bPlayDissolve = true)`、 `SetInstant(bool)` |
| 事件 | `OnSealReleased()`（宿主监听，用于解锁音效/箭头刷新） |
| 视觉语言 | 半透明发光罩 + **缓慢脉动**（呼吸感）；颜色偏青金。**宝箱 4 无前置、不需要罩**；宝箱 5 用球罩 Ø180；火方碑每根一个圆柱罩 Ø260×300 |
| 解除方式 | ① 宝箱（1·2·3·5）：**缓慢溶解消散**（1.2～1.8s，Dissolve 材质参数从下往上化掉）② 火方碑：每轮开关交互后**快速消失**（约 0.3s）；倒计时归零则**快速重新出现**（约 0.3s） |
| 碰撞（**关键**） | 罩子**绝对不能参与碰撞**：`CollisionEnabled = NoCollision`。否则会挡住玩家的交互射线，玩家按 E 打不到箱子/方碑 |
| 复用方式 | 在 `BP_LY_TreasureChest` 和 `BP_LY_FirePillar` 里各挂一个 `BP_LY_Seal` 子组件，逻辑由 C++ 的 `bIsSealed` / `bIsUnlocked` 驱动。**同一套代码同时服务「宝箱未解锁」和「方碑被封印」两种场景** |
| 易错点 | ① 罩子带碰撞 → 交互射线打不到宿主（**新手最容易踩**）② 消散用 Scale 归零 → 生硬，用 Dissolve 材质 ③ 罩子和宿主同为半透明 → 排序错乱、闪烁，宿主别用半透明材质 |
| 材质 | `M_LY_Seal`（母材质）+ `MI_LY_Seal_Chest` / `MI_LY_Seal_Pillar`（两个实例，颜色微调即可） |

## 🐛 常见坑

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 6 个机关各写一遍 | 无法复用，改一处要改六处，面试减分 | 全部继承 `ALY_MechanicBase`，只写差异 |
| 角度用 `==` 比较 | 旋转桥永远判定不对齐 | 用 `FindDeltaAngleDegrees` + 容差（约 5°） |
| 转盘只做一个方向 | 玩家转反了没法纠正 | 两个交互点：左 **−90°** / 右 **+90°**（3.3 / 3.14） |
| 旋转中允许再次交互 | 角度错乱、玩家被甩飞 | `bIsRotating` 时 `CanInteract` 返回 false |
| 环形索引没取模 | 谜题无解或崩溃 | `((i % N) + N) % N` |
| 谜题没有重置手段 | 玩家卡死，只能重开 | 全部熄灭自动重置，或提供重置拉杆 |
| 风场飞出地图/高度抖动 | 用了 AddForce 或没做柱顶迟滞 | 每帧直接写 `Velocity.Z`；柱顶 ±30 uu 迟滞 |
| 光路未激活却有碰撞 | 玩家走上去掉虚空 / 或提前到达终点 | 激活与碰撞同步开关 |
| 封印罩带了碰撞 | **交互射线打不到宝箱/方碑**，玩家按 E 没反应 | 罩子 `CollisionEnabled = NoCollision`（3.26） |
| 超时把已完成轮次也清空 | 玩家白做两轮，直接暴怒 | 只退回 `Sealed`，`CompletedRounds` 永久保留（3.15） |
| 倒计时每帧 Tick 累减 float | 长时间后时间会漂移 | 用 `SetTimer` + `GetRemainingTime()` 查询（3.15） |
