### 6.2 三个必须先解决的环境问题（按处理顺序）

#### 6.2.1 🔴 问题 1：C 盘只剩 18.3 GB，会被 UE 撑爆

UE5 默认把**派生数据缓存（DerivedDataCache，简称 DDC）**写到 `C:\Users\<用户名>\AppData\Local\UnrealEngine`。UE 5.5 起真正写盘的是 **Zen 存储层**，实际目录是 `...\UnrealEngine\Common\Zen\Data`；它会随着打开编辑器和编译着色器持续增长，轻易吃掉几十 GB。

**处理办法（见 6.7 的逐步操作）：**

1. ✅ **先设环境变量**，把 Zen DDC 指到 E 盘（这是唯一有效的做法）——**已经帮你设好了**，见 6.7.3。
2. 再清理 C 盘：旧的 Zen DDC、`%TEMP%`、Windows 更新缓存、休眠文件、微信/QQ 文件。
3. 长期把 `%TEMP%` 也挪到 E 盘。

> 这一条不解决，后面所有里程碑都会不稳。**这是 M0 的第一个任务。**

#### 6.2.2 🟡 问题 2：MSVC 14.44 对 UE 5.5 可能过新

UE 5.5 官方验证过的工具链大约在 14.38–14.40 一线。14.44 可能触发编译警告，极端情况会直接报错（UE 对编译器版本检查很严格）。

**处理办法（任选其一，优先第一个）：**

1. 用 Visual Studio Installer 确认已装 14.36 工具链，然后在 UE 的 `BuildConfiguration.xml` 里限制使用 14.36。
2. 直接试编译；如果 UE 能编译通过，就先用着，出问题再降版本。
3. 绝对不要为了「更新」而升级到最新的 MSVC——**项目期间不要动工具链**。

#### 6.2.3 🟡 问题 3：双显卡导致编辑器用核显跑

笔记本上，编辑器可能默认用 780M 核显渲染 → 卡顿、崩溃、打包后跑不动。

**处理办法：**

- NVIDIA 控制面板 → 管理 3D 设置 → 程序设置 → 添加 `UnrealEditor.exe` 和打包出的 `.exe` → 指定「高性能 NVIDIA 处理器」。
- Windows 设置 → 系统 → 屏幕 → 显示卡 → 给 `UnrealEditor.exe` 指定「高性能」。

## 第二部分 · 磁盘与 DDC（先解决头号风险）

### 6.6 第一步：清理 C 盘（目标：腾出 40 GB 以上）

按「收益从高到低」排序，做完前四项通常就够了。

#### 6.6.1 系统级清理（收益最大，5 分钟）

1. 键盘按 `Win + S`，搜索 **「磁盘清理」** → 选择 C 盘 → 点 **「清理系统文件」**。
2. 勾选这些（注意是「清理系统文件」模式才有）：
   - Windows 更新清理
   - 以前的 Windows 安装（如果有，**通常 5～20 GB**）
   - 临时文件、缩略图、传递优化文件
   - **不勾**「下载」文件夹（那可能是你的资料）
3. 确定，等它跑完。

**如果 C 盘有 `Windows.old`**（旧系统备份），它可能占 10～30 GB，一次就能解决问题。

#### 6.6.2 关掉休眠文件（收益 = 你内存的 40%～100%）

以管理员身份打开 PowerShell（开始菜单搜 PowerShell → 右键 → 以管理员身份运行），执行：

```powershell
powercfg /h off
```

这会关闭休眠（**不影响睡眠**），直接释放 `C:\hiberfil.sys`。
如果你内存 16 GB，这一步大约释放 6～13 GB；32 GB 内存则释放 12～26 GB。

> 代价：笔记本不能再「休眠」（Hibernate），但「睡眠」（Sleep）和关机都正常。对开发机完全够用。

#### 6.6.3 把虚拟内存（页面文件）挪到 E 盘（释放 5～20 GB）

1. `Win + R` → 输入 `sysdm.cpl` → 回车
2. 「高级」选项卡 → 性能「设置」→「高级」→ 虚拟内存「更改」
3. **取消勾选**「自动管理所有驱动器的分页文件大小」
4. 选中 C 盘 → 选「无分页文件」→ 点「设置」
5. 选中 E 盘 → 选「自定义大小」→ 初始大小和最大值都填 **16384**（16 GB）→ 点「设置」
6. 确定 → 重启电脑

> ⚠️ 如果你 C 盘是 SSD、E 盘是机械硬盘，这一步会让系统在极端缺内存时变慢。你的情况：先确认 E 盘是什么盘。**如果 E 盘是 SSD，放心移；如果是机械盘，只把大小调小（比如 4096），别完全关掉 C 盘分页文件。**

### 6.7 DDC 到底改对了没有？——实测结论：**没有生效**

> 直接回答你的问题：**你改的那行对“缓存不落 C 盘”没有作用；你的 DDC 现在仍然写在 C 盘。**
> 2026-09-26 实测：`C:\Users\19188\AppData\Local\UnrealEngine\Common\Zen\Data` 约 **676.8 MB / 158 个文件**，并且会继续增长。

#### 6.7.1 你改的是什么，为什么等于没改

你在 `E:\UE_5.5\Engine\Config\BaseEngine.ini` 的 `[InstalledDerivedDataBackendGraph]` 里改了：

```ini
Local=(Type=FileSystem, DeleteOnly=true, UnusedFileAge=8, Path="%GAMEDIR%DerivedDataCache", ...)
```

三个关键点：

1. `%GAMEDIR%` 在安装版引擎里指向**项目目录**，所以它只是把“项目级 Local DDC”指向项目下的 `DerivedDataCache`。
2. 这一行带 **`DeleteOnly=true`**：它主要参与**清理/删除旧缓存**，几乎不承担写入。
3. UE 5.5 真正写盘的是 **Zen 存储层**，由 `[Zen.AutoLaunch] DataPath` 决定，默认是：

```ini
[Zen.AutoLaunch]
DataPath=%ENGINEVERSIONAGNOSTICINSTALLEDUSERDIR%Zen/Data
```

在你的机器上，`%ENGINEVERSIONAGNOSTICINSTALLEDUSERDIR%` 展开为 `C:\Users\19188\AppData\Local\UnrealEngine`，所以真实写入目录是 **`C:\Users\19188\AppData\Local\UnrealEngine\Common\Zen\Data`**。

> 🎯 **结论**：你改的是“只负责删除的 Local 节点”，真正写盘的 Zen 层完全没动。**所以没有生效。**

> ✅ **2026-09-27 已在本机执行**（注意：上一轮设置因权限原因其实没写进注册表，09-27 已重新写入并当场核对通过）：

#### 6.7.4 其他占 C 盘的大头（你 C 盘只剩 18.3 GB）

实测：C 盘**已用 180.6 GB / 剩 18.3 GB**，E 盘剩 441 GB。主要占用：

| 位置 | 大小 | 建议 |
|---|---|---|
| `%LOCALAPPDATA%\Temp` | 约 2.4 GB | 可清理 |
| `%LOCALAPPDATA%\Packages` | 约 1.7 GB | 部分可清 |
| `%APPDATA%\lolBox` | 约 1.0 GB | 不用可卸载 |
| `%APPDATA%\npm` | 约 1.1 GB | 可执行 `npm cache clean --force` |
| 休眠文件 `hiberfil.sys` | 约内存的 40%～100% | 关闭休眠释放最多 |
| 页面文件（虚拟内存） | 5～20 GB | 可挪到 E 盘 |
| 微信/QQ 文件 | 常年 5～50 GB | 改存储位置到 E 盘 |

```powershell
# 关闭休眠（会同时关闭快速启动，可释放大量 C 盘空间）
powercfg -h off
# 清理临时文件（删不掉的跳过）
Remove-Item "$env:LOCALAPPDATA\Temp\*" -Recurse -Force -ErrorAction SilentlyContinue
```

#### 6.10.5 编译相关的常见报错速查

| 报错关键词 | 原因 | 解决 |
| --- | --- | --- |
| `The specified file was not found` / `MSB3073` | 项目路径或模块名不一致 | 检查 `.uproject` 里的 `Modules.Name` 和 `Source/` 文件夹名 |

| `UnrealHeaderTool failed` | `UCLASS/GENERATED_BODY` 写错 | 常见： `GENERATED_BODY()` 没写在类第一行、宏拼错 |
| `无法打开源文件 "xxx.generated.h"` | 文件名与类名不匹配 | 每个 `.cpp` 必须 `#include "ClassName.generated.h"`，且**放在所有 include 的最后一行** |
| `The project is not a C++ project` | 用蓝图模板建的 | 重建（见 6.9.1） |
| `Live Coding failed` | 改头文件时编辑器开着 | **改头文件 → 关编辑器 → 编译 → 再开**（见 `09_风险与踩坑速查.md`） |

### 6.16 项目名保持 `LiuYunCaveDemo`（已确认，不改）

**决定**：项目名**不改**，就用现在的 **`LiuYunCaveDemo`**。这一节从「改名教程」改成「一套名字用到底」的确认清单。亮

| 项目 | 值 |
| --- | --- |
| UE 工程文件 | `E:\UE_projects\LiuYun\LiuYunCaveDemo\LiuYunCaveDemo.uproject` |
| 模块名 / Source 文件夹 | `LiuYunCaveDemo`（`Source\LiuYunCaveDemo\LiuYunCaveDemo.Build.cs`） |
| 类名前缀（模板自带） | `ALiuYunCaveDemoCharacter`、`ALiuYunCaveDemoGameMode` |
| 编辑器目标名 | `LiuYunCaveDemoEditor` |
| 打包产物 | `LiuYunCaveDemo.exe` |

**为什么可以不改**：

- 改名的唯一动机是 `Cave` 名不副实（这是浮空遗迹、不是洞穴）。但**工程名不等于关卡设定**，面试时你讲的是「复刻留云借风洞天的机关玩法」，没人会因为工程文件夹叫 Cave 而误解。
- 你已经拿到**一次成功的编译**（`Binaries\UnrealEditor-LiuYunCaveDemo.dll` 已生成）——**已经跑通的工程不要动**，重命名的收益远小于风险。
- 真介意的话，**只改对外展示的名字**（README 标题、视频标题写「LiuYun / 留云借风洞天」）就够了，**工程名不用动**。

> 📌 **唯一要付的代价**（心里有数即可）：模板类名会一直叫 `ALiuYunCaveDemoCharacter`。**不用去改它**——`04_蓝图与C++协作.md` 里你会新建 `ALY_PlayerCharacter`，模板角色只当参考，两个名字互不冲突。

> ⚠️ **重要**：既然确定不改，就**别在中途改**。M8 之后再改工程名，会让 `.uproject` / `Source/` / 模块名三者不一致，编译直接失败并牵连 Git 历史。
