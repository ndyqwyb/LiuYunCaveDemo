## 第一部分 · 里程碑总体规划

### 8.1 总体节奏与假设

**假设**：每周投入 **12～18 小时**（工作日每天约 1.5 小时 + 周末每天 4 小时）。

**总周期**：**12 周（约 3 个月）**。这是「档位 B 且美术靠现成素材」的现实预估。如果你每周只能投入 6～8 小时，把周期乘 1.8（约 5 个月）。

**三条并行原则**：
1. **玩法先行**：M0～M8 只碰 gameplay 和灰盒，一旦「从头到尾能通关」，项目就算「成立」了。
2. **美术靠后且靠外**：M9 才导入美术，且 90% 用现成/免费/AI 素材。
3. **每周必须有一次「能玩」的状态**：不能出现「这周都在学理论，游戏打不开」的情况。

**难度与风险分布：**

```
M0  M1  M2  M3  M4  M5  M6  M7  M8  M9  M10 M11
▓▓  ▓▓▓ ▓▓▓ ▓▓  ▓▓▓ ▓▓▓ ▓▓▓ ▓▓  ▓▓▓ ▓▓▓▓ ▓▓  ▓▓
地基 手感 白盒 交互 火碑 桥 谜题 风场 组装 美术 演出 打包
                    ↑ 最容易卡             ↑ 最耗时
```

**M1 的具体操作（模板改造，不重写）**：
1. 在模板里找到 `BP_ThirdPersonCharacter`（或 C++ 类），看清楚它的组成： `CharacterMovement` + `SpringArm` + `Camera`。
2. **不要删模板类**，而是新建 `ALY_PlayerCharacter` **继承自模板角色类**（或直接把模板类重命名，二选一，推荐前者更安全）。
3. 把参数逐项调成 `02_关卡考据与设计.md` 的推荐值（移动速度、跳跃高度、相机臂长）。
4. **每调一次就 Play 一次**，凭手感决定，不要一次改十个参数。
5. 改完把输入资产重命名为 `IMC_LY_Default` / `IA_LY_*`。

> 💡 **「手感」没有标准答案，只有「你自己觉得舒服」。** 这是你第一次体会到「策划的感觉」——数值要自己试出来。

| 项 | 内容 |

| **做什么** | `ALY_RotatingBridge`（旋转石柱 + 光路对接判定）+ `ALY_LightPath`（暗/亮两种状态）+ 蓝图表现 |
| **依据** | `03_机关设计规格.md` 3.14 + `04_蓝图与C++协作.md` 4.18 |
| **产出** | 旋转石柱，转到正确角度时光路接通 |
| **验收** | ① **左转 −90° / 右转 +90° 都能用**；② 角度对齐判定正确（**核心难点，见下**）；③ 对齐时立刻有光/音反馈；④ 已接通后不再需要重转 |
| **常见卡点** | **角度比较用浮点数直接 `==`**（必然失败）、旋转方向混乱、光路的碰撞没跟着切换、旋转过程中重复触发 |
| **收尾** | `git tag M5` |

**本关最核心的技术点：角度对齐判定**
```
错误做法：if (CurrentAngle == TargetAngle)          // ❌ 浮点数永远不相等
正确做法：if (FMath::Abs(FMath::FindDeltaAngleDegrees(CurrentAngle, TargetAngle)) < 5.0f)  // ✅
```
> 这是全项目最容易被低估的一个坑（`09_风险与踩坑速查.md` 会再讲一次）。**先用调试输出把当前角度打在屏幕上，看着它转，你就懂了。**

### 8.9 M6 · 两处谜题（第 5～6 周，18～26 h）

这是玩法的**高潮**，也是最需要设计脑子的部分。

| 子阶段 | 内容 | 依据 |
| --- | --- | --- |
| **M6a** | 记忆顺序谜题（**⑥号岛**，宝箱 1·2·3）：每根方碑一个封印罩 + 每轮交互开关 + 独立递增倒计时（40/55/70s）+ 3 轮递增序列复现 | `02_关卡考据与设计.md` 流程阶段 4 + `03_机关设计规格.md` 3.15 + `3.26` |
| **M6b** | 联动翻转谜题（**⑩号岛**，宝箱 5）：点一根翻转自己 + 左右相邻，目标全亮 | `02_关卡考据与设计.md` 流程阶段 7 + `03_机关设计规格.md` 3.16 |
| | **产出** | 两处谜题都能独立通过 |
| | **验收** | ① 谜题规则正确（可在纸上验算）；② 支持重置；③ 完成后广播事件；④ 玩家能从视觉上理解「我该做什么」 |
| **常见卡点** | **环形数组的左右索引越界**、序列播放和玩家输入的时序冲突、全亮判定写错、谜题无法重置、**封印罩带碰撞挡住交互射线**、**超时误清已完成轮次** |
| | **收尾** | `git tag M6` |

**M6b 的核心算法（联动翻转）**：
- 6 个柱子排成环，玩家点第 `i` 个 → `i-1`、 `i`、 `i+1` 三个翻转。
- **环形的左右索引必须用取模**： `Left = (i - 1 + N) % N`、 `Right = (i + 1) % N`。
- **判定全亮**：遍历所有柱子，全部 `bIsLit == true` 才算完成。
- **解法验证**：初始状态为「灭」的柱子，**每个点一次**，因为每个柱子被自己点 1 次 + 被左右各点若干次……（**先在纸上模拟一遍**，确定你的初始状态是有解的！）。

> ⚠️ **最容易翻车的地方不是代码，是「谜题无解」或「谜题太简单」。** 在写代码之前，**用纸和笔把 6 个格子的状态画出来，手动推演一遍**。这一步花 20 分钟，能省你两天。

### 8.10 M7 · 风场与关卡流程（第 6～7 周，14～20 h）

| 项 | 内容 |
| --- | --- |
| **做什么** | ① `ALY_WindField`（零重力匀速电梯，**无滑翔**，**双向可通行**）② `ALY_Checkpoint` + 重生 ③ `ALY_GameFlowManager`（推进 8 个流程阶段）④ `ALY_KillVolume` |
| **依据** | `03_机关设计规格.md` |
| **产出** | 风场能把玩家 ⑦→⑧ 送上去、**也能 ⑧→⑦ 回来**；掉下去能重生；阶段会随进度推进 |
| **验收** | ① 进风场稳定上升到顶；② 不会飞出地图；③ 掉虚空回到最近检查点；④ 每个阶段的完成事件都正确触发 |
| **常见卡点** | 柱顶高度抖动、出柱没还原重力、施力写在风场侧导致时灵时不灵、重生后速度没清零、检查点顺序错乱 |
| **收尾** | `git tag M7` |

**风场的正确实现思路（关键 · 零重力匀速电梯）**：
```
进柱 → GravityScale = 0 / AirControl = 1.0
     → 上升段：Velocity.Z = RiseSpeed（每帧直接写，匀速）
     → 柱顶：Velocity.Z = 0，零重力只能动 XY（±30uu 迟滞防抖）
出柱 → 还原 GravityScale / AirControl → 正常重力接管 → 按 W 落到 ⑧号岛（顶面 +1200）
```
- **不要用 `AddForce`，也不要加速度累加**：速度会一直涨、飞出地图。
- **匀速靠"每帧写死速度"**，不是靠给力。
- **施力写在角色身上，不写在风场身上**：两个 Actor 的 Tick 顺序不确定。
- 完整参数表、几何验算、动画状态机见 `03_机关设计规格.md` 的 3.17。

> ⚠️ **原版 ⑦→⑧ 是「风场 + 滑翔」，本 Demo 删掉滑翔后改成「零重力匀速电梯」。** 玩家进柱后匀速上升、到顶悬停，**自己按 W 移出**落到 ⑧号岛。**反向 ⑧→⑦ 同理**，这就是玩家「上去还能下来」的保障。

#### 8.24.4 🔑 本周核心技术点：角度对齐判定

```cpp
// ❌ 错误做法：浮点数永远不会正好相等
if (CurrentAngle == TargetAngle) { /* 永远进不来 */ }

// ✅ 正确做法：算角度差，给容差
const float Delta = FMath::Abs(FMath::FindDeltaAngleDegrees(CurrentAngle, TargetAngle));
if (Delta < 5.0f) { /* 对齐成功 */ }
```

> ⚠️ **这是全项目最著名的坑，也是面试可以讲的故事。**
> 先用调试输出把角度打在屏幕上，**看着它转**，你就瞬间理解了。**这半天不能省。**

#### 8.25.4 🔑 本周核心技术点

**环形数组的左右索引（必须取模）：**

```cpp
const int32 Left  = (Index - 1 + Count) % Count;   // 不加 Count 会变负数！
const int32 Right = (Index + 1) % Count;
```

**风场的正确实现思路（零重力匀速电梯）：**

```
进柱  → GravityScale = 0 / AirControl = 1.0（★ 控制不是减弱，是调到最大）
      → 上升段：Velocity.Z = RiseSpeed（每帧直接写，匀速）
      → 柱顶：Velocity.Z = 0，零重力只能动 XY
出柱  → 还原 GravityScale / AirControl → 正常重力接管 → 按 W 落到 ⑧ 号岛
```

- **不要用 `AddForce`，也不要加速度累加**：速度会一直涨、直接飞出地图。
- **匀速靠"每帧写死速度"**，不是靠给力；进柱时用 0.2 秒从坠落速度插值到 `RiseSpeed`，避免"啪"一下。
- **施力写在角色身上，不写在风场身上**：两个 Actor 的 Tick 顺序不确定，会出现"时灵时不灵"。

> 💡 **原版 D→E 是「风场 + 滑翔」，本 Demo 删掉滑翔后改成「零重力匀速电梯」。**
> 玩家进柱匀速上升、到顶悬停，自己按 W 移出落到 ⑧号岛；**反向 ⑧→⑦ 同理**。**这个改动让 ⑦→⑧ 更简单，也更适合初学者。**

#### 8.25.5 🐛 本周常见卡点速查

| 症状 | 原因 | 解决 |
| --- | --- | --- |
| 数组越界崩溃 | 没做取模，负数索引 | 用上面的 `(Index - 1 + Count) % Count` |
| 谜题永远无解 | 初始状态是死局 | **纸上推演**；或先用「全灭」当初始状态 |
| 谜题太简单 | 只用 6 个柱子、初始全灭 | 调整初始亮灭模式增加步数 |
| 玩家越飞越快、飞出地图 | 用了 AddForce 或加速度累加 | 改成每帧直接写 `Velocity.Z = RiseSpeed` |
| 柱内按 W 几乎不往前走 | 没调 `AirControl`（默认约 0.05） | 进柱时设 `AirControl = 1.0` |
| 柱顶高度抖动 | 临界高度一帧升一帧停 | 加 30 uu 迟滞（`CeilingTolerance`） |

#### 8.29.4 🐛 本周常见卡点速查

| 症状 | 原因 | 解决 |
| --- | --- | --- |

### 8.34 每周日 5 分钟自检
